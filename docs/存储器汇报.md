## 0. 一页看完

| # | 存储器 | 容量/组织 | 实现 | 谁访问 | 关键信号 |
| --- | --- | --- | --- | --- | --- |
| 1 | **IMEM（IROM）** | 64 KB = 16 384 字 | `sync_mem_dp`（真双口 BRAM） | 端口 A：CPU 取指；端口 B：CPU 数据 / 引导器写 | `a_addr/a_ren/a_rdata`、`b_*` |
| 2 | **代码窗口** | 64 KB @ `0x0002_0000` | 就是 IMEM 的端口 B | CPU 的 `lw/lb/sw` | 无独立信号，靠 `soc_bus` 片选 |
| 3 | **DRAM** | 128 KB = 32 768 字 | `sync_mem`（单口）或 `dram_shared`（AXI 共享） | CPU 数据口；引导器；PS（AXI） | `addr/ren/rdata/wen/wdata/mask` |
| 4 | **DCache** | 256 行 × 32 b = 1 KB 数据 + tag/valid | `rtl/DCache.sv`（寄存器阵列） | LSU ↔ DRAM | `cpu_*` / `mem_*` / `m1_*` |
| 5 | **ICache（旁路）** | 64 行 × 32 b | `rtl/ICache.sv`（保留） | 现在不接，取指直连 IMEM | 仅作参考实现 |

一句话：**取指走 IMEM 的 A 口，数据走 DRAM 或代码窗口，MMIO 不缓存，PS 从 AXI 侧借 DRAM 的口。**

## 1. 存储器在全芯片里的位置

```
CPU（myCPU）
├─ IFU ─────────────► IMEM 端口 A   取指，只读，1 拍同步读
└─ LSU ─► DCache（256 行，写直达）
          ├─ 命中 ────────────────► 直接回数据（不停拍）
          └─ 缺失 ─► soc_bus ──┬─ MMIO 32 KB       0x1000_0000（不可缓存）
                                ├─ 代码窗口 64 KB   0x0002_0000 → IMEM 端口 B
                                └─ DRAM 128 KB      默认从设备（PS 可经 AXI 借用）
```

数据口的地址空间：

| 区间 | 名字 | 属性 |
| --- | --- | --- |
| `0x0000_0000 – 0x0001_FFFF` | DRAM 128 KB | 可缓存；`0x0_0000–0x0_FFFF` 是 ramdisk 空洞 |
| `0x0002_0000 – 0x0003_FFFF` | 代码窗口 64 KB | **不可缓存**；映射到 IMEM |
| `0x1000_0000 – 0x1000_7FFF` | MMIO 32 KB | 不可缓存，直通外设 |
| `0x0000_0000 – 0x0000_FFFF` | IMEM 64 KB（取指口） | 只有 IFU 能到 |

片选是三条掩码比较（`rtl/soc_map.sv:42-46`），没有加法器：

```
CODE : (addr & 0xFFFF_0000) == 0x0002_0000
MMIO : (addr & 0xFFFF_8000) == 0x1000_0000
DRAM : !CODE && !MMIO      ← 默认从设备
```

### 1.1 在 ILA / 波形里怎么找它们

| 存储器 | 实例名 | 模块 | 说明 |
| --- | --- | --- | --- |
| IMEM | `irom_inst` | `sync_mem_dp` | A 口取指、B 口数据/引导 |
| DRAM | `dram_inst` | `sync_mem` 或 `dram_shared` | 随 `AXIL_EN` 二选一 |
| DCache | `DCache_inst` | `DCache` | 在 `myCPU` 里 |
| AXI 从口 | `u_axil` | `axil_slave` | 仅 `AXIL_EN=1` |
| PS 控制面 | `u_ps_ctrl` | `ps_ctrl` | 仅 `AXIL_EN=1`，地址 `0x2_0000` 以上 |

层级前缀随顶层不同（纯 RISC-V 工程是 `board_top_ila → board_top → myCPU`；PS 工程是 `soc_ps_i → u_soc → u_top → u_cpu`），但**实例名不变**，按名字搜即可。

## 2. 统一契约：所有 BRAM 都按这一套走

这条契约写在 `board/sync_mem.sv` 头部，ICache/DCache 都是照它写的。**讲存储器先讲这四条**：

| # | 规则 | 含义 |
| --- | --- | --- |
| C1 | **读是"请求一拍、数据下一拍"** | T 拍给 `addr` 且 `ren=1`，T+1 拍 `rdata` 才有效（= `mem[addr(T)]`）；`ren=0` 时 `rdata` 保持上一次的值 |
| C2 | **写是单拍脉冲** | `wen` 为高的那一拍写入，**没有握手、没有 ready**；多给一拍就是多写一次 |
| C3 | **同拍读写同一地址，读口返回旧值** | 这是 BRAM 的常见语义；DCache 回填逻辑依赖它 |
| C4 | **复位只清 `rdata` 寄存器，不清存储阵列** | 真实 BRAM 的内容不会因复位被清空；所以 `dram_inst` 的 `.reset` 直接接 `1'b0` |

写宽度用 2 位掩码表达（`sync_mem.sv:70-75`）：

| `mask` | 写几个字节 | 落点由谁决定 |
| --- | --- | --- |
| `2'b00` | 1 字节 | `addr[1:0]` 选字节通道 |
| `2'b01` | 2 字节 | `addr[1]` 选低半字 / 高半字 |
| `2'b1x` | 4 字节 | 不看 `addr[1:0]`（非对齐字访问在 CPU 侧已被判异常） |

## 3. IMEM（IROM）64 KB —— `board/sync_mem_dp.sv`

哈佛结构里"取指的那一半"。v14 起给了**第二个读口**，这样软件能用 `lw` 读自己的代码/常量。

### 3.1 端口 A：取指（只读）

| 信号 | 方向 | 位宽 | 作用 | 口径/时序 |
| --- | --- | --- | --- | --- |
| `clk` | in | 1 | 50 MHz 系统时钟 | 与 CPU 同源 |
| `a_addr` | in | 32 | 取指字节地址 | 只有 `addr[15:2]` 参与字选择（16 384 字） |
| `a_ren` | in | 1 | 本拍发一次读 | = `irom_en`（ICache 旁路后就是 IFU 的取指使能） |
| `a_rdata` | out | 32 | 指令字 | `ren` 那拍给地址，**下一拍**有效 |
| `reset` | in | 1 | 只清 `a_rdata` | `board_top.sv:513` 接 `cpu_rst`，**不是** `cpu_rst_eff` |

> **关键不变量**（`board_top.sv:502-507`）：`reset` 必须只接 `cpu_rst`。如果接 `cpu_rst_eff`，引导期间复位一直是 1，`sync_mem` 的写逻辑在 `if (reset) ... else ...` 的 else 分支里 → 写会被整段丢掉，表现为"校验通过但一个字都没写进去"。

### 3.2 端口 B：CPU 数据读写 / 引导器写（互斥）

| 信号 | 方向 | 位宽 | 作用 | 口径/时序 |
| --- | --- | --- | --- | --- |
| `b_addr` | in | 32 | 数据访问地址 | 引导期间 = `boot_addr << 2`，正常 = `perip_addr` |
| `b_ren` | in | 1 | 本拍读代码窗口 | = `bus_re_code`（已被 `soc_bus` 按片选门过） |
| `b_rdata` | out | 32 | 读回的指令字 | 下一拍有效，进 `soc_bus` 的读回选 |
| `b_wen` | in | 1 | 本拍写 | 正常 = `bus_we_code`（CPU 的 store，单拍脉冲）；引导期间 = `boot_we & ~boot_mem_sel` |
| `b_wdata` | in | 32 | 写数据 | 正常 = `perip_wdata` |
| `b_mask` | in | 2 | 字节掩码 | 正常 = `perip_mask`；引导期间强制 `2'b11` |

**为什么两个读口够用**：Xilinx BRAM36 本来就是两个独立端口，多用一口**不增加 BRAM 数量**；2R1W 恰好落在"真双口 RAM"模板上（A 口只读、B 口读/写复用）。

> **综合坑**（`sync_mem_dp.sv:26-28`）：两个读口 + 一个写口必须写在**同一个 `always_ff`、同一个时钟**里，Vivado 才推成 True Dual Port RAM。拆成两个 `always_ff` 会被推成两块 RAM，**占用翻倍**。

### 3.3 代码窗口是怎么落到 IMEM 上的

`sync_mem_dp` 内部字地址固定为 `addr[ADDR_BITS+1:2]`，对 16 384 字就是 `addr[15:2]`（`sync_mem_dp.sv:60`）。

所以 `0x0002_0000 + 4n` 的 `addr[15:2]` 正好等于 `n` —— **窗口的高位（bit16、bit17）被忽略**，天然形成 64 KB 别名窗口：

```
CPU 读 0x0002_0000 + 4n  →  IMEM 第 n 个字
CPU 读 0x0000_0000 + 4n  →  DRAM 第 n 个字（不是 IMEM！）
```

这就是"为什么不能直接 `lw 0x0` 读自己的代码"的原因：取指口和数据口是两套独立译码。

## 4. DRAM 128 KB —— `board/sync_mem.sv` / `board/dram_shared.sv`

数据侧主存，放 `.rodata/.data/.bss/栈`，也是 PS 共享的那块内存。

### 4.1 CPU 口（两种实现共用同一套时序）

| 信号 | 方向 | 位宽 | 作用 | 口径/时序 |
| --- | --- | --- | --- | --- |
| `addr` / `cpu_addr` | in | 32 | 字节地址 | 字地址 = `addr[16:2]`（32 768 字） |
| `ren` / `cpu_ren` | in | 1 | 本拍读 | = `bus_re_dram`（只在命中 DRAM 时为 1） |
| `rdata` / `cpu_rdata` | out | 32 | 读回整字 | 下一拍有效，**由 LSU/WBU 按 `funct3` 抽字节** |
| `wen` / `cpu_wen` | in | 1 | 本拍写 | = `bus_we_dram`（已在总线里排除 MMIO / 代码窗口） |
| `wdata` / `cpu_wdata` | in | 32 | 写数据 | 字节写时数据在低位，由 `mask` 选通道 |
| `mask` / `cpu_mask` | in | 2 | 字节掩码 | 00/01/1x = 1/2/4 字节 |
| `reset` | in | 1 | 只清 `rdata` | `board_top.sv:770`、`:863` 都接 `1'b0` |

> **为什么 `reset` 接 0**：DRAM 阵列上电后由程序自己初始化，复位清阵列会把已加载的镜像/文件系统一起清掉。`sync_mem` 内部对 ≤4096 字做 `initial` 清零只是给 4 态仿真一个确定初值。

### 4.2 写保护：一次 `sw 0x1000_0000` 不能顺手改掉 DRAM

`bus_we_dram` 在 `soc_bus` 里已经排除了 MMIO 和代码窗口，所以 `dram_inst.wen` **不再做第二次地址判断**（`soc_bus.sv:33-34`）。这条踩过：不加保护时写串口会把 DRAM 第 0 个字改掉，症状是"打印一个字符，某个变量莫名其妙变了"。

### 4.3 AXI 共享口（`dram_shared`，仅 `AXIL_EN=1`）

| 信号 | 方向 | 位宽 | 作用 |
| --- | --- | --- | --- |
| `b_addr` | in | 32 | AXI 侧字节地址（BD 窗口内偏移） |
| `b_req` | in | 1 | 请求，**保持到 `b_gnt`** |
| `b_we` | in | 1 | 1 = 写，0 = 读 |
| `b_wdata` | in | 32 | 写数据 |
| `b_be` | in | 4 | AXI `wstrb` 原样，4 位字节使能 |
| `b_gnt` | out | 1 | 授权（当拍组合），= `wr_gnt \| rd_gnt` |
| `b_rvalid` | out | 1 | 读数据有效，**授权后下一拍**，单拍脉冲 |
| `b_rdata` | out | 32 | 读数据 |

**仲裁规则只有两条**（`dram_shared.sv:82-84`）：

```verilog
wr_gnt = b_req &  b_we & ~cpu_wen;   // CPU 要写 → PS 等
rd_gnt = b_req & ~b_we & ~cpu_ren;   // CPU 要读 → PS 等
```

- **CPU 永远赢**，且 mux 是组合的 → CPU 的访存**当拍就通，不被拖慢**（CoreMark 周期数逐拍不变可证）。
- 代价：CPU 与 PS **同拍写同一地址**时 PS 那一拍被忽略 —— 软件上约定"同一区域不要两边同时写"。
- 读数据只打**一拍**（`rdata_q`），两侧直接取用；多打一拍会让 load 拿到上一拍的旧值（第一版就这么错过）。

**为什么不是真双口**：Vivado 对"双口 + 两口字节使能"的阵列推断不出来（Synth 8-3391），而且 `xvlog` 编译 4×32768×8 的阵列要 400 s 以上，把 lint/SVA 门禁拖死。

## 5. DCache —— `rtl/DCache.sv`

- 组织：**256 行 × 1 字**，直接映射（`INDEX_BITS=8`，`TAG_BITS=22`），写直达 + 命中更新行
- 数据 1 KB + 256 个 tag + 256 个 valid（valid 打包成 256 位向量，`DCache.sv:101`）
- 地址 `≥ 0x1000_0000` 一律**不可缓存**（`UNCACHE_MASK = 0x0FFF_FFFF`）

### 5.1 CPU 侧（来自 LSU）

| 信号 | 方向 | 位宽 | 作用 | 要点 |
| --- | --- | --- | --- | --- |
| `cpu_en` | in | 1 | 本拍有访存 | **电平**，会被冻结保持多拍 |
| `cpu_wen` | in | 1 | 1 = store，0 = load | 电平，同上 |
| `cpu_addr` | in | 32 | 字节地址 | `index = addr[9:2]`，`tag = addr[31:10]` |
| `cpu_wdata` | in | 32 | 写数据 | 写直达，同时写 DRAM 和缓存行 |
| `cpu_mask` | in | 2 | 写宽度 | 透传给 DRAM |
| `cpu_adv` | in | 1 | **本拍这条访存真的推进了** | = LSU 的 `ready_next & ~lsu_freeze`；`store_fire = cpu_en & cpu_wen & cpu_adv` |
| `req_seq` | in | 1 | 请求身份证（每推进一条 M2 指令翻转） | 区分"同一条请求还在"和"同地址的下一条请求" |
| `cpu_rdata` | out | 32 | 回给 LSU 的**原始整字** | 字节抽取不在本模块做 |
| `inval` | in | 1 | 整表无效（双核用） | 1 的那拍把 256 个 valid 全清 |

**三个"必须"**（`DCache.sv:19-35`）：

1. `resp_valid_r` 少了 → 复位后第一拍拿复位值去比，把垃圾当"未命中"填进缓存行，`load` 恒读 `x`。
2. `addr_same_r` 少了 → 新地址第一拍就发 DRAM 读，返回的是上一个地址的数据（整体偏一个 index）。
3. `store_fire` 必须用 `cpu_adv` 判定。用"每拍都写"→ 同地址连写 4 拍；用状态机串行化 → 背靠背第二条 store **被静默丢弃**（v10.1 用随机差分测出来的真缺陷）。

### 5.2 DRAM 侧

| 信号 | 方向 | 位宽 | 作用 | 要点 |
| --- | --- | --- | --- | --- |
| `mem_addr` | out | 32 | 访存地址 | 读写共用寄存后的 `cpu_addr_r`，避免与脉冲错拍 |
| `mem_en` | out | 1 | 读请求 | **只高 1 拍**（一次 load 只读一次）；用 `~mem_en & mem_req_r` 标出"数据返回那拍" |
| `mem_wen` | out | 1 | 写请求 | 单拍脉冲，由 `store_fire` 产生 |
| `mem_wdata` | out | 32 | 写数据 | — |
| `mem_mask` | out | 2 | 写宽度 | — |
| `mem_rdata` | in | 32 | DRAM 返回 | 与 `mem_en` 差一拍 |
| `hold` | out | 1 | 需要停一拍重试 | 只在 load 缺失时拉高；回填后撤 |

### 5.3 观测与旁路

| 信号 | 方向 | 位宽 | 作用 |
| --- | --- | --- | --- |
| `hit` / `miss` | out | 1 | `hit` 在请求拍给出；`miss` 在**数据返回那一拍**记一次（MMIO 恒为"不驻留"，即恒 miss） |
| `hit_cnt` / `miss_cnt` | out | 32 | 命中/缺失计数（进 ILA） |
| `m1_addr` / `m1_en` | in | 32/1 | M1 级命中探测口（第二个只读口） |
| `m1_hit` / `m1_rdata` | out | 1/32 | M1 探测结果：命中当拍就能给数据，把 load-use 从 2 拍压到 **1 拍** |

### 5.4 一次 load 缺失的时序（文字波形）

关键表达式（`DCache.sv:202-225`）：

```verilog
hit_now      = cpu_en & ~cpu_wen & ~uncacheable_req & ~inval & valid[idx] & (tag==tag_in);
resp_for_now = mem_data_vld & idx/tag/addr 全对上;   // 数据返回那一拍
hold         = (cpu_en & ~cpu_wen) & ~(hit_now | resp_for_now);
cpu_rdata    = hit_now ? data[index] : mem_rdata;   // 命中取行，缺失直接给 DRAM 原始字
miss         = resp_for_now & ~hit_now;             // 缺失在“数据返回那一拍”才记一次
```

```
拍号        T              T+1              T+2
cpu_en      1              1                0        ← T 拍被 hold 冻住，请求保持
cpu_addr    0x10040        0x10040          —
mem_en      1              0                0        ← 只发一次读（单拍）
mem_rdata   —              data(0x10040)    保持
hold        1              0                0        ← 数据到位那一拍就撤
hit / miss  0 / 0          0 / 1            —        ← 缺失计数发生在返回拍
行回填      —              写 valid/tag/data 行生效（T+2 起同址 load 命中）
```

**代价 = 1 拍**：命中 1 拍出数据，缺失 2 拍出数据，多出的就是 T 那一拍。

> 这里踩过的坑（`DCache.sv:196-200`）：早期把 `| cache_rd_req` 放进 `hold`，会在**发出读的那一拍**就解掉 hold（数据还没回来），把总线残留值/X 锁进 `rdata_reg2`；反过来写成 `~hit & ~mem_req_r` 又会自己把自己锁死（load 之后整机停摆）。

## 6. ICache（已旁路）—— `rtl/ICache.sv`

**当前不参与取指**，保留作"以后把取指搬到 DDR/AXI"时的参考实现。列出来是因为它的端口仍是完整的：

| 信号 | 方向 | 位宽 | 作用 |
| --- | --- | --- | --- |
| `cpu_addr` | in | 32 | IFU 当拍要取的地址（**组合直通 BRAM**，不进寄存器） |
| `cpu_req` | in | 1 | 取指请求，可以每拍为 1 |
| `mem_addr` | out | 32 | = `cpu_addr` |
| `mem_en` | out | 1 | = `cpu_req`，只在真发请求那拍为 1（省 BRAM 动态功耗） |
| `mem_rdata` | in | 32 | BRAM 返回（1 级延迟） |
| `cpu_rdata` | out | 32 | 命中取 `data[]`，未命中**旁路** `mem_rdata`；`resp_valid=0` 时给 `NOP` |
| `resp_valid` | out | 1 | = `cpu_req` 打一拍，与 `mem_rdata` 同拍 |
| `hit` / `miss` | out | 1 | 命中 = `resp_valid && valid[idx] && tag 相等` |
| `clr` | in | 1 | `fence.i`：清全部 valid |
| `hit_cnt` / `miss_cnt` | out | 32 | 每**一次请求**记一次 |

**为什么旁路**（`myCPU.sv:322-333`）：在"BRAM 直连、固定 1 拍延迟"的结构下，ICache 对周期数和功耗的贡献**精确为 0** —— 命中也是 1 拍、缺失也是 1 拍（缺失直接旁路，不停拍）。留着它只会让"命中率"这个数字继续误导人。

## 7. 每根信号的"口径"速查

新手最容易错的是**地址切片**和**使能电平/脉冲**，一张表钉死：

| 存储器 | 字地址取哪几位 | 读使能语义 | 写使能语义 |
| --- | --- | --- | --- |
| IMEM A 口 | `addr[15:2]` | 电平，当拍请求 | — |
| IMEM B 口 | `addr[15:2]` | 电平，当拍请求 | 单拍脉冲（CPU store / 引导器） |
| DRAM（单口） | `addr[16:2]` | 电平，当拍请求 | 单拍脉冲 |
| DRAM（共享） | `addr[16:2]` | 同上 | 同上 |
| DCache 存储侧 | `addr[16:2]`（转发） | **只高 1 拍** | 单拍脉冲 |
| DCache 数组 | `addr[9:2]` index | 组合读 | 命中/回填时同步写 |

三条通用规则：

1. **低位是字节偏移，不参与字选择**（`addr[1:0]`）。
2. **`ren`/`wen` 必须分开分发**，不能合成一个 `req` 再拆（合了必然漏 store，`soc_bus.sv:21-24`）。
3. **读回选必须用 `hit_*`（纯译码），不能用 `sel_*`（含 ren/wen）** —— 数据在请求的下一拍才有效，那时 ren/wen 已经撤了，用 `sel_*` 会让读回变成 0。

## 8. 六条不变量（汇报时最值得讲的"坑"）

| # | 不变量 | 踩了会怎样 |
| --- | --- | --- |
| I1 | 写使能**只许在一处**判断（`soc_bus`） | 两处判断迟早对不上：写串口顺手改掉 DRAM 第 0 字 |
| I2 | `ren` 与 `wen` 分开分发 | 合成 `req` 会漏掉 store |
| I3 | 读回选用 `hit_*` 而非 `sel_*` | 读回恒 0 |
| I4 | `sync_mem` 的 `reset` 只清 `rdata` | 清阵列会毁掉固化/已加载的镜像 |
| I5 | `inval` 要进**所有**命中判定（DCache 四处） | 紧跟 invalidate 的那条 load 仍读到旧值（仿真抓出来的） |
| I6 | `store_fire` 用 `cpu_adv` 判定 | "每拍写"→ 写 4 次；状态机串行 → 第二条 store 被丢 |

## 10. 汇报提纲（10 分钟版）

1. **一张图**：取指走 IMEM A 口、数据走 DRAM/代码窗口/MMIO（§1）
2. **一条契约**：同步 BRAM 的"请求一拍、数据下一拍"（§2 C1）
3. **两个口**：IMEM 为什么是双读口（取指 + 代码窗口），为什么不多占 BRAM（§3）
4. **一个坑**：`reset` 接 `cpu_rst_eff` 会让引导"校验通过但没写进去"（§3.1）
5. **一次借用**：PS 借 DRAM 的口，CPU 永远优先（§4.3）
6. **一条流水**：load 缺失 → hold 一拍 → 回填 → 下一拍命中（§5.4）
7. **一个取舍**：ICache 为什么被旁路，为什么数据侧 DCache 必须留（§6）
8. **六条不变量**：写使能单点、ren/wen 分开、回选 hit_*、reset 不清阵列、inval 四处、store_fire 用 cpu_adv（§8）

## 附录 · 术语

| 术语 | 含义 |
| --- | --- |
| 字地址 | 字节地址除以 4；本设计取 `addr[N:2]` |
| 掩码（mask / be） | 2 位（CPU 侧）/ 4 位（AXI `wstrb`）字节使能 |
| 写直达 | store 同时写 DRAM 和缓存行，缓存永远不"脏"，无需回写 |
| 不驻留 | 该地址不占用缓存行（MMIO、代码窗口、未命中） |
| 旁路 | 不经缓存、直接把存储器返回的数据给 CPU |
| 回填 | 缺失时把读回的数据写进缓存行 + 置 valid + 存 tag |
| hold | DCache 请求 CPU 停一拍重试的信号（只在 load 缺失时） |
| 借空拍 | AXI 主机在 CPU 不访存的周期借用 DRAM 端口 |
