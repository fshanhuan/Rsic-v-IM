# HDMI 不出图 · 短接定位与修复单（2026-11-20）

> **一句话结论**：板上 `IIC_SCL_HDMI` 与 `IIC_SDA_HDMI`（HDMI 母座 **15 脚 / 16 脚**）
> 被连成了一个电节点。**不是 ADV7511 坏了，也不是软件问题** —— 两根 I2C 线短接，
> 从机永远解不出合法时序，于是 `0x39` 永不应答、永远没有画面。
> 本文只讲"怎么量、量到多少算什么、找到以后怎么改、改完怎么验"。

---

## 1. 证据（都是仪器读数，不是推断）

### 1.1 板上的三个判据

| 判据 | 实测 | 说明 |
|---|---|---|
| 两根线的 21 ms 占空比 | **每一对都逐拍相同**：65.17/65.17、87.95/87.95、14.21/14.21、34.64/34.64、0.38/0.38、79.61/79.61 | 独立两根线不可能做到 |
| **只按低 SCL**（VIO out6），等 400 ms 后读 | SCL=0，**SDA 也是 0** | 另一根被拖低 |
| **只按低 SDA**（VIO out7），等 400 ms 后读 | **SCL=0**，SDA=0 | 反向同样成立 |
| 放开后 | 两线都回到 12.99%~79.61% 的高电平 | 不是死锁，是外部把两根绑在一起 |
| 同期音频总线 `line_health` | 仍 **0x55**（ADAU1761 一直 ACK）| 只有 HDMI 这一对被短，别的总线正常 |

> 为什么"等 400 ms"很重要：`adv7511_init` 的重试周期是 200 ms，主控最多在一次
> 失败尝试后就回到等待并**释放两根线**。所以 400 ms 之后仍读到 0，只能是外部电路。

### 1.2 为什么这一切都说得通

| 现象 | 短接的解释 |
|---|---|
| `f_h=0x0000`，`init_done=0`，`ack_err` 每 4 s +35 | 时钟=数据，从机解不出地址 |
| `hdmi_scl == hdmi_sda` | 就是同一根线 |
| 健康总线空闲应 ≈99% 高，实测只有 0.4%~80% | 每个字节 SCL 拉低时 SDA 一起被拉低 |
| 冷上电、拔插 HDMI 线、换显示器都不变 | 静态短路，与时机无关 |
| 音频总线一直正常 | 那对脚（AA7/Y5）没短 |

## 2. 怎么量（断电，万用表通断/二极管档）

按顺序，**量到"通"就停**：

| 步 | 量哪里 | 正常应为 | 若为"通" |
|---|---|---|---|
| 1 | HDMI 母座 **15 脚 ↔ 16 脚** | 不通（>几百 kΩ）| **最常见**：相邻两脚焊锡搭桥 |
| 2 | U30（ADV7511）**55 脚 ↔ 56 脚** | 不通 | QFP 引脚之间搭桥 |
| 3 | FPGA **AB10 ↔ AB9**（BGA 球）| 不通 | 板内/球间短路（较罕见）|

> 若三步都不通，但上面的占空比判据仍然成立，则短路点在**走线中间**
> （过孔、静电阵列 U32/U33/U34 附近）—— 这时用放大镜沿 `SCL/SDA` 两条走线看锡渣。

---

## 3. 找到以后怎么改

| 位置 | 动作 |
|---|---|
| 母座 15/16 脚之间 | 加助焊剂 + 吸锡线拖一遍；放大镜确认两脚间无剩余锡桥 |
| U30 55/56 | 同上（QFP 脚距小，用细尖烙铁）|
| 静电阵列 U32/U33/U34 附近 | 检查是否有锡渣把 DDC 两条线连在一起 |

改完**不需要改任何 RTL / 重新综合**（除了下面第 4 步要烧回正常位流）。

## 4. 改完怎么验（三条命令）

```powershell
# ① 烧回"正常"位流（注意：板上现在是带下拉实验的位流，功能一样，但用这个更干净）
$env:PL_BIT = "E:\FPGA\v9_vivado_ila\v9_rec\v9_rec.runs\impl_1\board_top_rec.bit"
xsdb tools\ps\prog_pl.tcl

# ② 一条命令给判决
vivado -mode batch -source tools\ps\hdmi_check.tcl
```

判据（按顺序满足）：

| 指标 | 修好前 | 修好后应为 |
|---|---|---|
| `scl_hi_cnt` / `sda_hi_cnt` | 两个数**恒相等** | **两个数不再相等**（这是最好的第一信号）|
| `f_h` | `0x0000` | 非 0 且非 `0xFFFF`（`0x0002` = 0x39 应答）|
| `init_done` | 0 | **1** |
| `ack_err` | 每 4 s +35 | 停止增长 |

```powershell
# ③ 出图抓帧（判 GRID_80 = 我们的画面）
powershell -NoProfile -File tools\ps\hdmi_grab.ps1 -Tag after_short_fix
```

期望：`RESULT hdmi_grab verdict=... png=_diag\hdmi_after_short_fix.png`，
分析器认出**列峰 80 / 行峰 50**（即 S3 的 800×600 网格），此时 S1a 与 S3 的可见画面同时补齐。

## 5. 一句话教训（写给以后的自己）

> 两个独立观测量的读数**精确相等**时，先怀疑"它们测的是同一个东西"，
> 而不是去找一个能同时解释两个数的故事。
> 这条从第一次读数（65.17% / 65.17%）就摆在眼前，我却先按"最像的软件原因"
> 猜了两轮、白建了两次位流（约 100 分钟）—— 而真正的判据只值 10 秒的通断测量。
