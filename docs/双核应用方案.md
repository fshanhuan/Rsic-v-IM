## 0. 结论：四个方案

| 方案 | 用到什么 | 新增 RTL | 新增软件 | 工作量 | 双核用得上吗 | 一句话卖点 |
| --- | --- | --- | --- | --- | --- | --- |
| **A 确定性脉冲** | J5 + 数码管 + 拨码 | `pulse_gen`、`seg7` | 参数设置环 | **3 天** | 是（ARM 在线改参数） | 脉冲由硬件分频，抖动 **0 拍** |
| **B 硬件触发采集** | XADC（J5-9/13） | `adc_capture` + 环形缓冲 + PLIC 源 5 | 取块、打包 | **4.5 天** | 是（ARM 存盘/上报） | 采样节拍与 CPU 负载**无关** |
| **C 无线网关** | WiFi232（AA17/AB17）+ PS SD | 第二路 UART + FIFO | WiFi AT + FatFS | **4 天** | **强**（WiFi 归 RISC-V，SD 归 ARM） | 不装 Linux 也能无线上云 |
| **D 组合（推荐）** | A+B+C | 复用 | 复用 | **7–10 天** | 三条链路全用 | 确定性采集 + 无线回传 + 主处理器看护 |

D 是最终形态，但**先做 B**：B 是地基（硬件节拍 + 共享内存 + 中断），A 和 C 都复用它的基础设施。

> 所有方案另需一次 **P0：MMIO 索引 4→6 位**（0.5 天，见 §2.1）—— 现在只有 16 个寄存器号，不够放新外设。

## 2. 公共底座（已建成，所有方案复用）

这四条是所有方案的共同地基，**不需要重新发明**：

| 能力 | 现状 | 位置 |
| --- | --- | --- |
| 共享 DRAM 128 KB | CPU 与 PS 同时访问，CPU 优先不丢拍 | `board/dram_shared.sv` |
| CPU→PS 门铃 | 写 `0x1000_001C` bit1 → `irq_ps` → GIC | `board_top.sv` |
| PS→CPU 门铃 | PS 写 `CTRL.bit1` → PLIC 源 4 → MEIP | `board/ps_ctrl.sv` |

**约定一块信箱**（方案 A/B/C 共用）：

```
共享 DRAM 128 KB
0x0_0000 – 0x0_FFFF   ramdisk（不动）
0x1_0000 – 0x1_EFFF   程序 .data/.bss/栈
0x1_F000 – 0x1_FFFF   ★ 双核信箱 4 KB（本方案新增，链接脚本要让出）
    +0x00  MAGIC     0x5A5A_0001
    +0x04  SEQ       RISC-V 每写一块 +1
    +0x08  LEN       本块字节数
    +0x0C  FLAGS     bit0=数据块, bit1=错误, bit2=心跳
    +0x10  TS_LO/TS_HI  RISC-V 侧 mtime
    +0x20  负载（最多 4 KB − 32 B）
```

### 2.1 前置任务 P0：MMIO 索引从 4 位扩到 6 位

**这是所有方案的第一颗螺丝，必须先拧。** 现在 `soc_bus` 的寄存器号是 `addr[5:2]`（**4 位，只有 16 个**，`0x00–0x3C`），而本方案要加的寄存器从 `0x40` 起 —— 不扩位就会全体别名到 0–15。

| 要改的地方 | 改法 |
| --- | --- |
| `rtl/soc_map.sv` | 新增 `SOC_MMIO_IDX_*` 定义，索引位宽注释改 6 位 |
| `board/soc_bus.sv` | `mmio_idx = addr[5:2]` → `addr[7:2]`（**输出宽度 4→6**） |
| `board/board_top.sv` | MMIO 读回 `case` 与写使能判断补上新寄存器 |
| `tools/gen_soc_map.py` → `sw/soc_map.h`、`docs/地址表.md` | 重新生成 |
| 回归 | `_diag/regress.ps1` 里的 `soc_map` 用例 + `tb_bus` + `tb_monitor` |

**兼容性**：`0x00–0x3C` 的偏移**一个都不动**，老软件不用改 —— 只是把"4 位索引"改成"6 位索引"，高位地址不再折叠。这和当年 3 位→4 位（`0x20` 与 `0x00` 别名，撞 LED）是同一种改动。

> 若不想动总线：把新外设放到**独立窗口**（`0x1000_8000` 以上，仍在 MMIO 32 KB 内），用第二套片选。但那样每个外设都要多一套译码，不如扩位干净。

**以下所有寄存器偏移都假设 P0 已完成。**

## 3. 方案 A：确定性脉冲 + 数码管位置显示

### 3.1 定位

用硬件产生严格周期的 step 脉冲，CPU 只负责"设定速度/加速度/目标位置"。**抖动由硬件分频器决定，与软件负载无关** —— 这是运动控制唯一可辩护的做法。

### 3.2 分工

| 谁 | 干什么 | 为什么不能换 |
| --- | --- | --- |
| **RISC-V** | 硬件 `pulse_gen` 按 `PERIOD` 输出 STEP/DIR；读编码器回环计数；把位置写数码管 | 脉冲抖动必须 = 0 拍 |
| **ARM** | 在线改速度/方向/目标位置；记录轨迹；演示时通过串口下发 | 参数计算与日志是软件活 |

### 3.3 新增 RTL：`rtl/pulse_gen.sv` + `board/seg7.sv`

**寄存器（MMIO，接 `soc_bus`）**

| 偏移 | 名字 | 读写 | 说明 |
| --- | --- | --- | --- |
| `+0x40` | PLS_CTRL | RW | bit0 使能，bit1 方向，bit2 软停 |
| `+0x44` | PLS_PERIOD | RW | 半周期拍数（50 MHz / (2f)），最小 2 |
| `+0x48` | PLS_COUNT | RW | 剩余脉冲数，写即装载 |
| `+0x4C` | PLS_POS | RO | 已发脉冲数（位置） |
| `+0x50` | PLS_STAT | RO | bit0 busy，bit1 done，bit2 回环失步 |

**模块要点**

```verilog
// 硬件分频：半个周期切换一次 STEP，计数器从 PERIOD 递减到 0
// ★ 不变量：PERIOD 在运行中写入时，下一个半周期才生效（不打断当前半周期）
always_ff @(posedge clk) begin
    if (half_cnt == 0) begin step_r <= ~step_r; half_cnt <= period_r - 1; end
    else half_cnt <= half_cnt - 1;
end
```

`seg7` 是纯扫描显示：8 位动态扫描（1 kHz），把 `PLS_POS` 以十进制显示在 8 位数码管上。

### 3.4 引脚

| 信号 | 引脚 | 说明 |
| --- | --- | --- |
| `step` | **U17**（J5-1） | 脉冲输出 |
| `dir` | **U15**（J5-3） | 方向 |
| `step_loop` | **W16**（J5-5） | 杜邦线跳回 U17，做自检计数 |
| 数码管 24 根 | 见 §1.2 | 段选/位选 |

**无外部器件也能演示**：U17 用杜邦线跳 W16，RISC-V 自己发脉冲自己数；`PLS_STAT.bit2` 在丢步时置位。

### 3.5 验收判据

| 判据 | 方法 | 期望 |
| --- | --- | --- |
| 脉冲抖动 | ILA 抓 `step` 上升沿间隔 | **恒定 N 拍（N = 2×PERIOD），方差 0** |
| 在线改速 | ARM 写 `PERIOD`，看数码管频率变化 | 下一周期生效，不丢脉冲 |
| 回环不丢步 | `COUNT=10000`，比较发送数与回环数 | 差值 = 0 |
| 位置显示 | 数码管读数 vs `PLS_POS` | 一致 |

### 3.6 工作量与风险

- RTL 2 天（脉冲 0.5 + 数码管 1 + 总线/引脚 0.5），软件 0.5 天，上板 0.5 天
- 风险：**数码管极性**（共阴 + 三极管反相）需先用 `PLS_POS` 全 8 试一遍；J5 串了 200 Ω，接长线时边沿会变缓，50 kHz 以内没问题

## 4. 方案 B：XADC 硬件触发采集（推荐先做）

### 4.1 定位

**采样节拍由硬件定时器产生，与 CPU 在干什么完全无关**。这一条比"软件循环采样"强一个数量级 —— 也是"确定性"最硬的证据。

### 4.2 分工

| 谁 | 干什么 | 为什么不能换 |
| --- | --- | --- |
| **RISC-V** | `adc_capture` 按 `DIV` 硬件节拍触发 XADC，打时间戳写环形缓冲；半满中断取块；判断阈值 | 节拍抖动必须为 0 |
| **ARM** | 取块写 SD（历史曲线）、参数下发、可选用以太网/串口上报 | 存储与协议栈 |

### 4.3 新增 RTL：`rtl/adc_capture.sv`

```
DIV 分频器 ──► tick ──► XADC(DRP 读 AD6/AD11) ──► {ts, ch0, ch1} ──► 环形缓冲 1024×64
                                                                    └─► 半满/满 → PLIC 源 5
```

**寄存器**

| 偏移 | 名字 | 读写 | 说明 |
| --- | --- | --- | --- |
| `+0x60` | ADC_CTRL | RW | bit0 使能，bit1 通道选择（AD6/AD11），bit2 清缓冲 |
| `+0x64` | ADC_DIV | RW | 分频值：f_s = 50 MHz / DIV（1 kHz → 50 000） |
| `+0x68` | ADC_WR | RO | 写指针（已采样本数低 10 位） |
| `+0x6C` | ADC_RD | RW | 读指针（软件写，硬件不碰） |
| `+0x70` | ADC_STAT | RO | bit0 半满，bit1 满，bit2 溢出过 |
| `+0x74` | ADC_LAST | RO | 最近一次 {ch0[15:0], ch1[15:0]} |

**关键设计点**

1. **时间戳来自 CLINT `mtime`**（500 kHz，2 µs 分辨率），与采样同沿锁存 —— 软件换算成绝对时间不会漂。
2. XADC 用 DRP 读，ADCCLK = DCLK/2 = 25 MHz，一次转换 ≈ 1.04 µs，远小于 1 kHz 周期。
3. 缓冲用**双口 BRAM**（写口硬件、读口 CPU），1024×64 bit = 8 KB = 2 tile。
4. **溢出必须可观测**：`ADC_STAT.bit2` 一旦置位就保持，直到 `ADC_CTRL.bit2` 清 —— 演示时"拔掉 CPU"可以直接看到。

### 4.4 引脚与信号源

| 信号 | 引脚 | 说明 |
| --- | --- | --- |
| `vauxp6` / `vauxn6` | **V13 / W13**（J5-13/14） | AD6 差分对；单端用时 N 端接模拟地 |
| `vauxp11` / `vauxn11` | **A18 / A19**（J5-9/10） | AD11 |

**信号源（全部板载）**：DAC0832 输出 0–3.98 V 经两只电阻分压到 0–1 V，回灌 J5-13 —— 板上自闭环，可软件生成正弦/斜坡测试采集链路。

### 4.5 验收判据

| 判据 | 方法 | 期望 |
| --- | --- | --- |
| **采样间隔抖动** | ILA 抓 `tick` 间隔；或读回相邻时间戳差 | **恒定 DIV 拍，方差 0** |
| 抗负载干扰 | CPU 同时跑 CoreMark，再测间隔 | **完全不变**（这是卖点） |
| 不丢点 | 写入递增序列号，读回校验 | 连续 10⁶ 点无空洞 |
| 精度 | 输入已知电压（分压后） | 12 bit 码值误差 ≤ 2 LSB |

### 4.6 工作量与风险

- RTL 3 天，软件 1 天，上板 0.5 天
- 风险：**XADC 与 PS 的占用冲突** —— Zynq 的 XADC 在 PL 侧，但 PS 也能通过 DRP 访问；需确认 BD 里没有启用 PS 的 XADC 通路（待确认项 §9-3）

## 5. 方案 C：WiFi 透传 + SD 存档

### 5.1 定位

板上 **WIFI232-A 是 UART 透传模块**，RISC-V 接一路 UART 就能收发 TCP —— **完全绕开 Linux 和 BSP**。SD 卡在 PS 侧，正好归 ARM。

### 5.2 分工

| 谁 | 干什么 | 为什么不能换 |
| --- | --- | --- |
| **RISC-V** | 第二路 UART 接 WiFi232：AT 配置 → 透传模式 → 每 100 ms 发一包采样数据 | 实时发包不能被 OS 调度拖延 |
| **ARM** | PS SDIO + FatFS 写 CSV；参数配置；心跳看护 | 文件系统与存储 |

### 5.3 新增 RTL：第二路 UART

复用现成的 `board/uart_tx.sv` / `board/uart_rx.sv`（参数化 `CLK_FREQ`/`BAUD`），新增 3 个寄存器：

| 偏移 | 名字 | 读写 | 说明 |
| --- | --- | --- | --- |
| `+0x78` | U2_TXDATA | WO | 发一个字节 |
| `+0x7C` | U2_RXDATA | RO | 收一个字节（幂等 peek） |
| `+0x80` | U2_STAT | RO | bit0 TX 忙，bit1 RX 有数据，bit2 RX 溢出 |

**引脚**

| 信号 | 引脚 | 方向（按信号名） |
| --- | --- | --- |
| `wf_rx`（FPGA→模块 RX） | **AA17** | output |
| `wf_tx`（模块 TX→FPGA） | **AB17** | input ⚠ 手册写的是 OUTPUT，**待确认** |
| `wf_reset` | **U19** | output（模块硬复位） |
| RTS/CTS | AA16 / AB16 | 可先不用 |

### 5.4 软件流程

```
RISC-V: 复位模块 → AT 查版本 → AT+WJAP 连路由 → AT+WKMOD 透传 → 进入数据模式
        每 100 ms: 打包 [magic, seq, ts, ch0..ch7] → UART2 发送
ARM:    轮询信箱（门铃中断）→ 取块 → 写 SD /data/YYYYMMDD.csv → 更新索引
```

### 5.5 验收判据

| 判据 | 方法 | 期望 |
| --- | --- | --- |
| WiFi 连通 | 手机 TCP 客户端连模块 | 收到连续数据包 |
| 丢包率 | 包内 seq 连续性 | <0.1%（局域网） |
| SD 写入 | 拔卡后插到 PC 读 CSV | 行数 = RISC-V 发送包数 |
| 断网不影响采集 | 拔掉 WiFi 再插回 | 采样间隔不变，溢出位不置（缓冲够） |

### 5.6 工作量与风险

- RTL 1 天，WiFi AT 调试 1 天，PS 侧 SD/FatFS 2 天
- 风险：WIFI232 配置命令随固件版本不同（需实际读回 `AT+VER`）；PS 侧裸机 SD 驱动是主要工作量

## 6. 方案 D：组合（推荐最终形态）

```
                      ┌──────── XADC（J5-13）◄── DAC0832 分压回灌
                      │
   RISC-V ──► adc_capture（硬件节拍）──► 环形缓冲 ──┬──► UART2 ──► WiFi232 ──► 手机/PC
      │                                            │
      │ 超阈值/半满                                └──► 共享 DRAM 信箱 0x1_F000
      │                                                        │ 门铃中断
      ▼                                                        ▼
   数码管/脉冲（可选）                                     ARM：写 SD CSV
                                                          轮询心跳，挂了就 HOLD 重载
```

**三条卖点一次讲完**：

1. **确定性**：采样节拍由硬件分频器决定，ILA 证明抖动 = 0 拍（方案 B）
2. **异构协同**：WiFi 归 RISC-V（实时）、SD 与看护归 ARM（文件系统）—— 各自不可替代（方案 C）
3. **可维护**：ARM 能在运行中重载 RISC-V（现有 `ps_ctrl` 能力，已上板验证）

| --- | --- | --- |
| 现有（时钟/复位/UART/LED） | 12 | — |

## 9. 待确认清单（上板前必须查清）

| # | 事项 | 怎么查 | 影响 |
| --- | --- | --- | --- |
| 1 | 数码管段选/位选极性（共阴 + 2N5551 反相） | 先点亮一位，全 8 段轮询 | 显示全反会"黑屏" |
| 2 | WiFi 模块 `WF_RX` 的真实方向（手册两行都写 OUTPUT） | 万用表/示波器看空闲电平，或试接 | 接反会打架 |
| 3 | XADC 是否被 PS 占用（DRP 冲突） | 查 BD 里 PS7 的 XADC 选项；先单独例化 XADC 读温度 | 冲突则读数恒 0 |
| 4 | XADC 单端接法（N 端是否需接地） | 接 0.5 V 已知电压，读数应 ≈ 2048 | 否则读数漂 |
| 5 | J5 的 200 Ω 串阻对 50 kHz 边沿的影响 | 示波器看上升时间 | 高频时需降速 |
| 6 | DAC0832 输出摆幅与分压比 | 万用表量 VREF 与满码输出 | 超过 1 V 会损坏 XADC |

## 10. 风险与规避

| 风险 | 概率 | 规避 |
| --- | --- | --- |
| XADC 读数不稳/为 0 | 中 | 先跑"读芯片温度"最小例程验证 DRP 通路，再接外部通道 |
| 数码管扫描与 CPU 访存抢总线 | 低 | 扫描时钟独立分频，不经过 `soc_bus` |
| WiFi 模块固件差异导致 AT 命令不通 | 中 | 先 `AT` 回车看回显，再 `AT+VER` 记录版本 |
| PS 侧裸机 SD 驱动踩坑 | 中高 | 先用 FAT32 小卡 + 固定簇；不行就退回"串口打印 CSV" |
| 新增外设把 WNS 拉负 | 低 | 每个外设都是同步逻辑、独立时钟域内；加完重跑 `build_project_boot.tcl` 看 WNS |
