## 1. 接线清单

| 口 | 用途 | 必需？ | 说明 |
| --- | --- | --- | --- |
| **J3**（USB3.0） | 供电 + JTAG + PS UART1(COM13) | **必需** | 供电不足时改用外部 5V 适配器，但 J3 仍要留着 |
| **J8**（USB2.0 母口） | PL UART（CP2103） | 强烈建议 | 插对时 Windows 出现新 COM（本项目里是 COM9） |
| HDMI 口 | 显示器 | S1a/S3 需要 | 不插显示器时 HPD 为低，ADV7511 不应答 I2C |
| **DAC 输出：J2-1**（丝印 `VOUT_0832`，J2-2 = GND）| 模拟信号源 | S2 自环需要 | 码 0x00=0 V，0xFF=**+3.98 V**；复位就是 0xFF（满量程）|
| 分压（330 Ω 串 + 100 Ω 并地 = **1:4.3**）| 把 0~3.98 V 压到 0~0.926 V | S2 自环需要 | **必须先分压再接**，直连 3.98 V 会打坏 XADC；接反（100 串/330 并）会得到 3.07 V |
| 接 XADC：**J5-9(P)/J5-10(N)** = AD11（默认通道）| 模拟自环 | 当前位流默认 | 手册 §16；J5 每根 IO 串 200 Ω，不影响直流 |
| 或 **J12-1(P)/J12-2(N)** = AD10 | 模拟自环 | 需 `board_top_rec_S2_3ch` + `ch_sel=1` | 手册 §27 |
| 或 **J21-1(P)/J21-2(N)** = AD2 | 模拟自环 | 需 `board_top_rec_S2_3ch` + `ch_sel=2` | 手册 §27 |
| — | 板载 LED | 观察 | CPU 在写 LED 寄存器（idx 4） |

> ⚠️ **电源灯 D18 不亮就别继续**：先查总电源开关、供电方式选挑插针（USB / 外部 5V 二选一）。

| `col_col` / `col_wr` | 在跳，`col_col` 扫 0..799 | CPU 正在推列摘要 |
| `col_wr_bank` | 每帧翻一次 | 双 bank 提交生效 |

### 三个 JTAG 控制位（都不占引脚）

| 环境变量 | 作用 | 用法 |
| --- | --- | --- |
| `VIO_RESCAN=1` | 重跑一轮 I2C 扫描 | 插/拔显示器后重新判定 S1a |
| `VIO_INTH=1` | 采样通道换片内温度 | 证明 XADC 真在转换 |
| `VIO_TRIG=1` | 强制触发自检（电平+阈值0） | 验证 S4，期望 ≈3125 次/秒 |

## 5.5 上电即跑：记录仪自己就会跑（**不需要串口**）

从 2026-11-17 15:48 那版位流起，记录仪主循环已经**固化在比特流里**：

```
上电 → 引导器等 500 ms 串口（等不到就放弃）→ CPU 从 0 开始跑记录仪
     → 每帧写 800 列（一条 MMIO 写 = 一整列）→ 每 8 帧刷一次测量面板
```

也就是说：**J8 串口没通，也能看到波形上屏**。串口要是以后通了，它仍然优先：
引导器收到合法镜像会覆盖固化镜像，开发流程一点没变。

### 5.5.1 怎么判断它真的在跑

| 探针 | 期望 | 不满足说明什么 |
| --- | --- | --- |
| `d_wb_pc` | 落在 **0x0..0xA08** | 若一直停在 0x00..0x38，跑的还是 v18 那 14 条演示指令 → 固化镜像没进网表 |
| `col_col` | 两次采样**不同**，范围 0..799 | 不动 = 主循环没进/卡在等 ADC |
| `col_wr_bank` | 两次采样可能不同（每帧翻） | 不翻 = 提交（0xA8）没生效 |
| `adc_level` | 小于 FIFO 深度（不是满的） | 一直满 = CPU 没在排空 |

采样两次即可：


## 5.6 S2 自环：一条命令扫出整条 DAC→ADC 曲线（2026-11-19 新增）

上一版只能"多次读 `dac_byte` / `adc_last`，看读数在动"，属于定性证据。
这一版位流里加了硬件扫描器（`board/adc_sweep.sv`）：**每个码停 1 ms、累加 16 个
新样本、求平均、存表**，256 个码约 277 ms 扫完，采样时码值是静止的 ——
所以"读数与码值同时"这个要求不再靠读得快来满足。

```powershell
& 'D:\vivado\2025.2\Vivado\bin\vivado.bat' -mode batch -nolog -nojournal -notrace `
    -source 'E:/FPGA/v9_vivado_ila/_diag/s2_curve.tcl'
```

它会自动：选 AD11(J5) → 关三角波 → 启动扫描 → 逐条读回 256 点 → 最小二乘拟合，
最后打印一行

```
[S2C] RESULT s2_curve_done verdict=CURVE_OK slope=... inter=... maxres=... monotone=1
```

| `verdict` | 含义 / 下一步 |
| --- | --- |
| `CURVE_OK` | 码值→读数是线性单调的，S2 的"可判定"部分完成 |
| `NO_SIGNAL` | 斜率≈0：模拟线没接、或 P/N 接反（§48.15 就是 P/N 接反） |
| `NON_MONOTONE` | 有下降段：查分压接触、地线、或两路信号串扰 |
| `NONLINEAR` | 最大残差偏大：多半是一头/两头饱和，看表里 mV 列在哪里开始不涨 |
| `INCOMPLETE` | `rd_ok=0` 的条目太多：扫描没跑完（先看 `SWEEP_ST` 的 busy/done） |

顺带产出 `_diag/s2_curve.csv`（`code,adc_avg,adc12,mV,ok`），可以直接拿去画图。

> ⚠️ **2026-11-19 17:00 实测的坏消息**：这条命令能启动扫描（`done=1`、结束码 0xFF），
> 但**把 256 条读回 PC 的那一步在这块板上不可靠** —— 用 VIO 输出当读指针时，
> 写下去的指针在硬件里不跟随（写 100 后 4.1 s 内 41 次回读一次都没变）。
> 症状是"高段连续几百条一模一样"。**别把这种表当真值用。**
> 可靠的替代是下面这条（三角波 + 原子配对，已实测可重复）：

```powershell
& 'D:\vivado\2025.2\Vivado\bin\vivado.bat' -mode batch -nolog -nojournal -notrace `
    -source 'E:/FPGA/v9_vivado_ila/_diag/s2_ramp_curve.tcl'
# 产物 _diag/s2_ramp_pairs.csv（n,code,adc_raw,adc12,mV），320 点覆盖 ~180 个码
```

它每一对 `(dac_byte, adc_last)` 都来自**同一次 VIO 刷新**（同一个时钟沿），
所以配对严格同时；按码分箱后在 PC 上求均值/拟合即可。

**想改稳定时间或平均次数**：这两个是 MMIO 寄存器（`0xE0` / `0xE4`），
需要用 CPU 程序写；只走 JTAG 时用硬件默认值（1 ms / 16 次），不必重建位流。

> 提醒：分压换成 3.3 kΩ + 10 kΩ 之后，读数会变成接近 0~0.93 V 的满量程，
> 那时斜率约为现在的 4 倍，`maxres` 也该同比变小。

## 7. 步骤 5：显示（S1a / S3）

### 7.1 它会自己配置

上电后硬件状态机会**每 200 ms 重试**配置 ADV7511（14 条寄存器写，
含 ADI 必写项 + 视频格式 + 最后退出掉电）。所以：

1. 插上显示器；
2. 等 1～2 秒；
3. 读 VIO 看 `init_done=1`（`init_no_dev=0`），屏幕应出现网格 + 波形区。

### 7.2 屏幕不亮的排查顺序

| 顺序 | 检查 | 判据 |
| --- | --- | --- |
| 1 | `init_no_dev` 是否还是 1 | 还是 1 → I2C 根本没有应答，先解决 S1a |
| 2 | 手动重扫：`VIO_RESCAN=1` | `f_h` 应从 0 变成 0x0002（0x39 应答） |
| 3 | `init_done=1` 但画面是黑 | 改视频格式寄存器（0x15/0x16/0x17/0x18），用 `i2ctool` 单改 |
| 4 | 画面有但颜色不对 | 同上，重点 0x18（CSC） |
| 5 | 画面撕裂一条竖线 | `recorder` 的 `tears` 计数；应为 0（commit 机制） |

### 7.3 看波形

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File _diag/put_app.ps1 -Name recorder -Port COM9
# 终端： run recorder
```

`recorder` 每帧把 ADC FIFO 里的样本按 800 列分配、算 min/max、写 `0x80`，
写完一帧写 `0xA8=1` 提交。屏幕上应出现一条随信号变化的波形。

## 9. 常见坑清单（都是真踩过的）

| # | 坑 | 症状 | 对策 |
| --- | --- | --- | --- |
| 1 | I2C `SCAN_BASE` 是 7 位地址 | 一个 ACK 都没有 | ADV7511 = 7 位 `0x39`，基址给 `0x38` |
| 2 | 扫描地址用 `\|` 拼 | 位图出现幽灵应答（`found=0x0202`） | 必须用 `+` |
| 3 | 状态机发请求不等完成 | 把 START 的 `done` 当成地址字节 → 全 NACK | 请求后必须等 `m_done` 再推进 |
| 4 | holdoff 按"拍"递减 | 触发率高出 3 倍 | 只在 `sample_valid` 那拍递减 |
| 5 | `logic x = 1'b0;` 声明处赋初值 | iverilog 当线网，多驱动/初值失效 | 用 `initial` 块赋值 |
| 6 | 状态变量未初始化（X） | 从机永远走不到 ACK | 显式 `initial` 赋值 |
| 7 | `func(idx)[15:8]` | 语法错 | 先赋给 wire 再取位段 |
| 8 | 先用后声明 | `xvlog` 报 `used before declaration` | 声明写在前面 |
| 9 | 替换锚点不唯一 | 端口接到别的实例上（`Synth 8-11365`） | 锚点必须在目标实例内唯一 |
| 10 | 像素域/CPU 域直接传单拍脉冲 | 25 ns 脉冲过二级同步会整个丢 | 电平翻转 + 同步 + 边沿还原 |
| 11 | 一帧行数 +1 | 数成 629 | 一帧内恰好 628 个 hsync 下降沿，不要 +1 |
| 12 | vsync 变低那一拍被清零吃掉 | 4223 而非 4224 | 锁存时 +1 补回 |
| 13 | DAC 复位值给 0 | 输出 3.98 V 顶在 1 V 的 XADC 脚上 | 复位给 `0xFF`（≈0 V） |
| 14 | AD6(V13/W13) 想用 3.3 V | `DRC BIVC-1` bank 电压冲突 | 只用 AD11，或该 bank 改 1.8 V |
| 15 | 固定"每列 4 样本" | FIFO 每帧净增、约 9 帧溢出 | 按 `ADC_LVL` 可用量分配 |

| 19 | 1.8 V 排针 / 上拉判断 | — | `line_health = 0x55` 表示四根线都到过高/低 |

| 24 | 大改动直接用 `AggressiveExplore` | 布线跑 3h45m 仍未收敛 | 先用 `Default` 验功能，再用 `Explore` 收时序 |
| 25 | 把 MMIO 寄存器读当成"读一次就够" | 连续读**不同**寄存器时读到上一条的值（记录仪：FIFO 占用数 1024 读成 0/1） | 已于 DCache 根治（syn/修复史_全量.md §DCACHE-7）；软件里

## 10. S5 / S7 一条命令复现（PS 侧排空 + CSV）

前置：板上跑的是记录仪位流、JTAG 正常。整个流程会自动换位流、跑完再换回来。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File E:\FPGA\v9_vivado_ila\tools\ps\s5_demo.ps1 -N 1024
```

脚本做四步（每步之间清掉残留 `hw_server`）：

| 步 | 动作 | 期望输出 |
| --- | --- | --- |
| 1 | 烧 `_baseline_v9/board_top_ps_rec_S5.bit` | `[PG] prog S5: 0` |
| 2 | `tools/ps/arm_drain.tcl` 排空 N 个样本 | `[DRAIN] 循环次数=…` `标记=BEEF0005` `RESULT=DRAIN-PASS` `RESULT=RUNLEN-PASS` |
| 3 | 烧回 `board_top_rec_S6_autorange.bit` | `[R] prog: 0` + `Legacy Debug Hub` |
| 4 | 读 VIO 复核记录仪 | `adc_cnt` / `m_frame_clk=663168` / `meas_*` |

实测（2026-11-18 01:28，N=1024）：游程 `45 + 128×7 + 83`，中间 7 段全 128，
期间 Δ`adc_cnt`=1024 → **严格 200 kSa/s**，汇总 `排空 PASS / 游程连续 PASS`。
产物：`sim/build/drain_<时间戳>.csv`（列：`index,raw_hex,code_dec,voltage_v`）。

> 如果第 2 步报 `HALT-FAIL（核卡在总线访问上…）`：说明上一次实验把 PS 互连挂死了，
> **断一次电**再来。正常情况不会出现——程序自带 SLCR 前置与自检（坑 30）。

### 10.5 SD 卡写入：一条命令（2026-11-18 新增）
