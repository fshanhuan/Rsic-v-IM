# 模块速查 · 按 `.sv` 文件逐个说明（v17 / 当前 `rtl/` + `board/`）

> 用途：**快速认识这个 CPU**——每个文件是干什么的、主要输入输出是什么、信号是什么意思。
> 口径：以当前 `rtl/`、`board/` 的真实代码为准（端口名逐字取自源码），不是设计意图。
> 老文档 `docs/模块说明.md` 里有大量"当时怎么定位 bug"的叙事，仍然可读；但其中
> ICache、load 只在 M3 可前递、除法 34 拍等描述**已被现在的 RTL 取代**，以本文为准。

---

## 0. 先建立三个坐标系

### 0.1 逻辑五级 ↔ 物理八级

教材口径是五级；这个核**逻辑上是五级，物理上有 8 个寄存器边界**（ID 拆 2 拍、MEM 拆 3 拍）。
拍数变多是为了让每级组合逻辑短到能跑 50 MHz，指令语义没变。

| 逻辑级 | 物理拍 | 主要模块 | 这一级在干什么 |
|---|---|---|---|
| **IF** | IF | `IFU` + `ICache`(旁路) + `Branch_Predictor` | 生成 PC、查 BTB/PHT、发取指、4 项取指队列 |
| **ID** | ID1 → ID2 | `IDU` + `Reg_Stack`(GPR+CSR) + `Data_hazard` | ID1 抓指令；ID2 译码、读寄存器、算立即数、选前递 |
| **EX** | EX | `EXU` + `ALU` + `MDU_pipelined` | 运算、算分支/跳转目标、比对预测、判定异常 |
| **MEM** | M1 → M2 → M3 | `LSU` + `DCache` | M1 地址就绪/命中探测、M2 发总线、M3 数据回来 |
| **WB** | WB | `WBU` | 选最终写回值、写通用寄存器、提交 CSR |

### 0.2 信号命名约定（看懂名字就看懂一半）

| 后缀 / 前缀 | 含义 |
|---|---|
| `*_next` | 本级**输出给下游**的值（下一拍的输入） |
| `*_reg`、`*_r` | 本级的锁存寄存器 |
| `*_pipe` | LSU 的**第 2 拍**（M2，真正发总线那一拍） |
| `*_wb` | LSU 的**第 3 拍**（M3，直接给 WBU） |
| `IDU_*` / `EXU_*` / `MEM_*` / `MEM2_*` / `WB_*` | "站在某级看"的同一根值，给前递/冒险用 |
| `alu_op` 的 `bit[4]=1` | 表示这是 **RV32M** 指令（交给 MDU，不进 ALU） |
| `mask[1:0]` | 字节使能：`00`=字节 `01`=半字 `10`=字（= `funct3[1:0]`） |
| `csr_wen[15:0]` | CSR 写使能**位图**，一位一个 CSR（不是地址译码） |

### 0.3 握手只有一种

每一级都有 `valid_last`（上游给的）/ `ready_last`（本级能不能收）和
`valid_next` / `ready_next`（给下游的）。**只有 `valid & ready` 同拍为 1，这条指令才推进一步。**
`IFU→IDU→EXU` 走这套；`LSU→WBU` 不等（WBU 恒 `ready=1`），所以写回不会反压。

### 0.4 哪些文件真的参与编译

| 文件 | 综合 | 说明 |
|---|---|---|
| `rtl/` 下 21 个（含 `para.sv`、`MDU_pipelined.sv`） | ✅ | `build_project_boot.tcl` 逐条列出 |
| `rtl/MDU.sv` | ❌ | 老的单拍组合乘除（3 个并行乘法器），只作对照 |
| `rtl/ICache.sv` | ⚠️ 列了但**没有例化** | v11 起取指直接走 IROM + 队列，ICache 被旁路 |
| `board/board_top_vivado.sv`、`board/tb_board_top.sv` | ❌ | 早期 Vivado/仿真顶层，已不用 |
| `project_src/board_top_gui_boot.sv` | ✅ | 真正的板级外壳（MMCM 100→50 MHz + ILA + 引脚） |

## 1. 取指级（IF）

### 1.1 `rtl/IFU.sv` —— 取指单元（PC 生成 + 4 项取指队列）

**干什么**：维护 PC；把 PC 发给 ICache/IROM；把回来的指令按顺序交给 IDU；收到重定向请求
（`dnpc_flag`）时**无条件**把 PC 改成 `dnpc`。队列深度 4，用来吸收 load-use（1 拍）、
DCache 未命中（2 拍）、MDU 忙（17 拍）的抖动。

| 主要输入 | 含义 |
|---|---|
| `dnpc[31:0]`、`dnpc_flag` | 重定向目标 + 单拍请求（来自 Control） |
| `irom_data[31:0]`、`inst_valid` | 取回的指令 + 本拍有效（来自 ICache/直连 BRAM） |
| `pred_taken`、`pred_target`、`pred_index` | 分支预测结果（来自 Branch_Predictor，组合） |
| `ready` | 下游 IDU 能不能收（结构性背压） |

| 主要输出 | 含义 |
|---|---|
| `ic_addr[31:0]`、`ic_req` | 本拍要取的地址 + 取指使能（给 ICache/BRAM） |
| `snpc[31:0]`、`pc[31:0]`、`inst[31:0]` | 顺序 PC / 当前 PC / 指令，交给 IDU |
| `fetch_pc[31:0]` | 取指侧 PC（给 BPU 查表） |
| `pred_taken_out`…`pred_index_out` | 预测信息随指令一起带下去（EX 级做比对） |
| `valid` | 本级有有效指令交给下游 |

**坑**：`dnpc_flag` 只有一拍宽，**不能被 `ready` 门控**，否则重定向永久丢失（v9 B9 的事故）。

### 1.2 `rtl/Branch_Predictor.sv` —— 分支预测（BHT + BTB + RAS）

**干什么**：IF 级组合查表给出"跳不跳、跳哪"；EX 级用真实结果回写并统计。
256 项 PHT（2 位计数器）+ 256 行 BTB + 8 位 GHR（PC 低位 XOR）+ 8 深 RAS（call/ret）。

| 主要输入 | 含义 |
|---|---|
| `fetch_pc[31:0]` | IF 级要预测的 PC |
| `update_en`、`update_pc`、`update_index` | EX 级回写使能 / PC / 表项索引 |
| `update_taken`、`update_target`、`update_correct` | 真实方向 / 目标 / 预测对错 |
| `update_is_call`、`update_is_ret` | 给 RAS 做 push/pop 的分类 |

| 主要输出 | 含义 |
|---|---|
| `pred_taken`、`pred_target[31:0]`、`pred_index` | 组合预测结果 |
| `pred_cnt`/`hit_cnt`/`miss_cnt` | 预测次数 / 命中 / 失败（性能统计） |

### 1.3 `rtl/ICache.sv` —— 指令缓存（**v11 起已旁路，不参与综合逻辑**）

**干什么**：本来是 64 行直接映射 I-Cache。v11 把取指改成"队列 + 直连 IROM 同步读"后，
它不再被例化；文件保留作为将来接真 cache 的起点。所以**现在取指没有 cache 命中/缺失**，
`debug_icache_*_cnt` 恒 0。

保留的端口（若要恢复）：`cpu_addr/cpu_req`（请求）、`mem_addr/mem_en`（→BRAM）、
`resp_valid/hit/miss`（响应）、`clr`（fence.i）。

## 2. 译码级（ID1 → ID2）

### 2.1 `rtl/IDU.sv` —— 译码 + 读寄存器 + 立即数

**干什么**：ID1 抓指令，ID2 完成：译码出全部控制位、生成 5 种立即数、经 `Reg_Stack`
读 rs1/rs2/CSR、把前递选择（`Data_hazard` 给的 choice）打到操作数上、算分支目标 `branch_pc`、
判非法指令与访存非对齐。

| 主要输入 | 含义 |
|---|---|
| `inst_in[31:0]`、`pc_in`、`snpc_in` | 指令 / 当前 PC / 顺序 PC |
| `flush`、`stall` | 冲刷（灌 NOP）/ 冻结 |
| `rd_value`、`rd`、`R_wen`、`csr_wen` | WB 级写口（写 GPR / 写 CSR） |
| `EXU_rs1_in`、`EXU_rs2_in` | 上游已锁存的寄存器值（用于前递基线） |
| `sys_commit_ok` | 本拍 ecall/mret **确实会提交**（门控 CSR 副作用） |
| `trap_take`、`trap_cause`、`fault_addr/inst/pc` | 异常通道（透传给 `Reg_Stack` 里的 CSR） |
| `retire` | 一条指令真正退休（只给 `minstret` 计数） |

| 主要输出 | 含义 |
|---|---|
| `rd_next`、`R_wen_next`、`csr_wen_next[15:0]` | 目的寄存器 / 写 GPR / 写哪个 CSR |
| `alu_opcode[4:0]` | ALU 操作码（`bit4=1` → MDU） |
| `rs1_value`、`rs2_value`、`add1_value`、`add2_value` | 前递后的操作数 / 送 ALU 的两个数 |
| `mem_ren`、`mem_wen`、`funct3` | 访存类型（load/store + 宽度） |
| `branch_flag`、`jump_flag`、`inv_flag` | 分支 / 跳转 / 分支取反 |
| `branch_pc[31:0]` | 分支目标地址 |
| `illegal_flag`、`mem_misalign`、`mem_misalign_funct3` | 异常预判（EX 级锁存后上报） |
| `inst_d_out[31:0]` | 译码级指令本体（给 EXU 当 `mtval` 来源） |
| `csr_sel[15:0]` | 本拍要读的 CSR 独热码（配合 `csr_rd_fwd` 做 RAW 前递） |

### 2.2 `rtl/Reg_Stack.sv` —— 寄存器堆 + CSR 的容器

**干什么**：里面例化 `RegisterFile`（32×32 GPR）和 `CSR`；对外只暴露"读两个源 + 读一个 CSR"
和一堆 CSR 观察口。x0 恒 0，`a0_value` 固定读 x10（给调试/打印用）。

| 主要输入 | 含义 |
|---|---|
| `rs1`、`rs2` | 组合读地址（ID 级） |
| `rd`、`rd_value`、`R_wen` | 写口（WB 级） |
| `csr_addr[11:0]`、`csr_wen[15:0]`、`csrd[31:0]` | CSR 读地址 / 写位图 / 写数据 |
| `trap_take`、`trap_cause`、`fault_*` | 异常登记通道 |

| 主要输出 | 含义 |
|---|---|
| `rs1_value`、`rs2_value`、`a0_value` | GPR 读值（x10 专用口） |
| `csrs[31:0]` | CSR 读值（`csrr*` 的返回） |
| `mepc_out`/`mtvec_out`/`mcause_out`/`mtval_out`/`mstatus_out`… | 各 CSR 直通观察口 |
| `mcycle_out[63:0]`、`minstret_out[63:0]` | Zicntr 计数器 |
| `intr_pending` | `mstatus.MIE` 被置位，且 `mie` 与 `mip` 至少有一位同时为 1 |

### 2.3 `rtl/RegisterFile.sv` —— 32×32 通用寄存器堆

**干什么**：两读一写，组合读、同步写，`x0` 恒 0。端口：`rs1_addr/rs2_addr → rs1_value/rs2_value`、
`waddr/wdata/wen` 写口、`a0_value` 固定读 x10。
**注意**：模块的**默认参数写反了**（`ADDR_WIDTH=32, DATA_WIDTH=5`），实际例化是
`RegisterFile #(5, 32)`（`Reg_Stack.sv`）——别照默认值理解位宽。

### 2.4 `rtl/CSR.sv` —— 控制状态寄存器组

**干什么**：M 模式 CSR：`mepc/mcause/mtvec/mtval/mstatus/mie/mip/mscratch/mtime/mtimecmp`
+ `mvendorid/marchid`（常量）+ Zicntr 的 `mcycle/minstret`。负责异常登记（`trap_take` 单拍写
`mepc/mcause/mtval`）、`ecall/mret` 的 `mstatus` 变更、中断挂起计算。

| 主要输入 | 含义 |
|---|---|
| `pc[31:0]` | 译码级 PC（`ecall` 的 mepc 来源之一） |
| `ecall_flag`、`mret_flag`、`intr_take` | 系统指令 / 中断接收 |
| `trap_take`、`trap_cause[3:0]`、`fault_addr`、`fault_inst`、`fault_pc` | 同步异常登记（`trap_cause` 是 `EXC_*` **独热码**） |
| `csr_wen[15:0]`、`csrd[31:0]` | 软件写哪个 CSR / 写什么 |
| `retire` | 退休脉冲（`minstret` 的唯一计数使能） |

| 主要输出 | 含义 |
|---|---|
| `mepc_out`/`mcause_out`/`mtvec_out`/`mtval_out`/`mstatus_out`… | 各寄存器当前值 |
| `mcycle_out[63:0]`、`minstret_out[63:0]` | 周期数 / 退休指令数 |
| `intr_pending` | 有中断待处理 |

**坑**：`mtval` 曾有"写了但没 `assign` 出来"的漏驱动，导致软件永远读到 0。

### 2.5 `rtl/Data_hazard.sv` —— 前递仲裁 + load-use 判定

**干什么**：比较 ID 级要读的 `rs1/rs2` 和各在途级的 `rd`，决定操作数从哪来（本级/EX/M1/M2/M3/WB），
并判定 load-use 冒险要不要停拍。v15 起用 DCache 的 M1 探测口，把 load-use 从 2 拍压到 **1 拍**。

| 主要输入 | 含义 |
|---|---|
| `IDU_rs1`、`IDU_rs2` | ID 级要读的两个源寄存器号 |
| `EXU_rd`、`MEM_rd`、`MEM_PIPE_rd`、`MEM2_rd`、`WB_rd` | 各级的目的寄存器号 |
| 各级 `valid`、`R_Wen`、`mem_ren` | 该级有没有、写不写、是不是 load |
| `MEM_m1_ok` | M1 探测口命中：MEM 级本拍就能当前递源且不必停拍 |

| 主要输出 | 含义 |
|---|---|
| `IDU_rs1_choice[2:0]`、`IDU_rs2_choice[2:0]` | 前递选择（本级/EX/M1/M2/M3/WB 里选一个） |
| `load_use_stall` | 需要把 ID/前端按停（进 `IFU_stall`） |
| `exu_load_use`、`mem_load_use`、`pipe_load_use` | 分级明细，给波形与调试看 |

## 3. 执行级（EX）

### 3.1 `rtl/EXU.sv` —— 执行级本体

**干什么**：锁存操作数 → 送 `ALU` 算 → 同时解析分支/跳转（目标、是否真跳、与预测比对）→
与 MDU 做多拍握手（乘 1 拍、除 17 拍）→ 锁存异常标志 → 产出交给 LSU 的一整套 `*_next`。
还负责 valid/ready 的"接收/放行"门控（`up_stall`、`bp_pend`、`trap_take`）。

| 主要输入 | 含义 |
|---|---|
| `add1`、`add2`、`rd_value`、`rs2_value` | 操作数 / 写回值（jal 的 link、CSR 读值） |
| `alu_opcode[4:0]`、`inv_flag` | ALU 操作 / 条件取反 |
| `branch_flag`、`jump_flag`、`branch_pc` | 分支/跳转控制与目标 |
| `pred_taken_in`、`pred_target_in`、`pred_index_in` | 预测结果（用于比对） |
| `illegal_in`、`mem_misalign_in`、`mem_misalign_funct3_in`、`fault_inst_in` | 异常输入（与 IDU 同拍） |
| `valid_last`、`ready_next`、`up_stall`、`bp_pend`、`trap_take` | 握手与门控 |

| 主要输出 | 含义 |
|---|---|
| `EX_result[31:0]` | 运算结果（对 load/store 是**有效地址**） |
| `branch_pc_next`、`rd_value_next`、`rs2_value_next` | 继续下传的操作数/目标 |
| `funct3_next`、`rd_next`、`csr_wen_next`、`R_wen_next`、`mem_wen_next`、`mem_ren_next` | 控制位下传 |
| `mdu_busy`、`mdu_done` | MDU 忙 / 本拍结果有效（`busy` 会冻结整机） |
| `illegal_exc`、`mem_misalign_exc`、`iaddr_misalign_exc`、`fault_inst_exc` | 已锁存的异常标志（给 Control 定优先级） |
| `inst_reg_exc[31:0]` | 已寄存的指令原码（BPU 做 call/ret 分类） |
| `valid_next`、`ready_last` | 握手 |

### 3.2 `rtl/ALU.sv` —— 整数运算单元

**干什么**：纯组合。加法（复用给减/比较/分支方向）、逻辑、移位、比较、`bitclr`（CSRRC 用）。
RV32M 的编码落到 `default` 返回 0 —— M 指令不在这里算，走 MDU。
端口：`d1[31:0]`、`d2[31:0]`、`choice[4:0]` → `res[31:0]`。比较结果只放 `res[0]`。

### 3.3 `rtl/MDU_pipelined.sv` —— RV32M 乘除法（实际在用的那个）

**干什么**：EX 级旁的多拍单元。乘法**1 拍**出结果（单个无符号 32×32 → 64 位积，符号在器外
用 abs + 64 位条件取反修正），除法 **16 拍 radix-4 迭代 + 1 拍结果窗口 = 17 拍**，期间
`busy` 冻结整机。三条快路径（除零、`|a|<|b|`、div/rem 配对缓存）只要 1 拍。

| 主要输入 | 含义 |
|---|---|
| `start` | EX 级发射一条 M 指令（单拍） |
| `d1[31:0]`、`d2[31:0]` | 被乘数/被除数、乘数/除数 |
| `op[4:0]` | `bit4=1` 才是 M；`bit2` 选乘/除；`bit[1:0]` 选具体操作 |

| 主要输出 | 含义 |
|---|---|
| `res[31:0]` | 结果（只在 `done` 那拍有效，EXU 必须锁存） |
| `busy` | 除法迭代中（→ 整机冻结） |
| `done` | 本拍结果有效（单拍） |

DSP：整机 4 个 DSP48E1 全在这一个乘法器上；除法不占 DSP（LUT+CARRY）。

### 3.4 `rtl/MDU.sv` —— **旧版**（单拍组合乘除，不参与编译）

三个并行乘法器（`prod_ss/prod_su/prod_uu`）+ 组合除法器，面积大、组合路径长，
是"整机最长路径"的历史来源。留作对照，别照着它改。

## 4. 访存级（M1 → M2 → M3）

### 4.1 `rtl/LSU.sv` —— 访存流水线（内部三级）

**干什么**：把 EX 送来的地址/数据排成三级：**M1** 地址与命中断言、**M2** 真正发总线
（`addr/wen/wdata/mask`）、**M3** 数据回来并做字节/半字选道与符号扩展。同时产出两套前递值
（`forward_val_pipe` / `forward_val_wb`）和 WB 入口的 `retire_wb`。`mem_hold`（DCache 缺失）
或 `mdu_busy` 时**整条流水冻结**。

| 主要输入 | 含义 |
|---|---|
| `mem_ren`、`mem_wen`、`funct3`、`Ex_result`、`rs2_value` | 访问类型 / 宽度 / 地址 / 写数据 |
| `R_wen`、`rd`、`rd_value`、`jump_flag`、`pc` | 写回目标与 link 值 |
| `rdata[31:0]` | DCache 回来的**原始整字**（选道在本模块做） |
| `m1_hit`、`m1_rdata` | DCache M1 探测口命中（本拍就能拿到数据） |
| `mem_hold`、`mdu_busy` | 冻结请求 |

| 主要输出 | 含义 |
|---|---|
| `addr[31:0]`、`wen`、`wdata[31:0]`、`mask[1:0]` | 给 DCache/总线的访存请求 |
| `rdata_wb_raw`、`rdata_offset_wb[1:0]`、`funct3_wb` | M3 的原料：原始整字 + 地址低 2 位 + 宽度 |
| `forward_val_pipe`、`forward_val_wb` | M2/M3 的前递值 |
| `LSU_Rdata_m1`、`m1_load_ok` | M1 命中路径的数据与"可用"标志 |
| `retire_wb` | 一条指令真正退休（给 `minstret`） |
| `valid_pipe`、`valid_wb`、`pc_wb`、`*_wb` 一组 | 给 WBU 的整组信号 |

**坑**：store 的"发过一次"必须用**推进**判定（`cpu_adv`），否则同一条 store 会写多拍。

### 4.2 `rtl/DCache.sv` —— 数据缓存（1 KB 直接映射，写直达）

**干什么**：256 行 × 1 字；命中当拍给数据，未命中向 DRAM/IROM 窗口发**一次**读、`hold` 冻结
LSU 一拍后回填；store 是写直达 + 命中同步合并缓存行。地址 > `0x0FFF_FFFF` 视为 MMIO
（不可缓存：命中恒 0、不填行、直通外设）。

| 主要输入 | 含义 |
|---|---|
| `cpu_en`、`cpu_wen`、`cpu_addr`、`cpu_wdata`、`cpu_mask` | CPU 侧访存请求（来自 LSU 的 M2） |
| `cpu_adv` | LSU 本拍真的推进（决定 store 只写一次） |
| `req_seq` | 请求身份证（区分"同一条还在"和"同地址的下一条"） |
| `mem_rdata[31:0]` | 存储器回来的数据 |
| `m1_addr`、`m1_en` | M1 命中探测口（v15，把 load-use 降到 1 拍） |

| 主要输出 | 含义 |
|---|---|
| `cpu_rdata[31:0]` | 给 LSU 的原始整字（选道在 LSU/WBU 做） |
| `mem_addr`、`mem_en`、`mem_wen`、`mem_wdata`、`mem_mask` | 去 board_top 三路译码的访存请求 |
| `hit`、`miss`、`hold` | 本次访问结果 / 需要停一拍重试 |
| `m1_hit`、`m1_rdata` | M1 探测命中 + 数据 |
| `hit_cnt`、`miss_cnt` | 命中/缺失次数 |

**坑**：`hit`/`miss` 两个端口在 RTL 里**没有读者**（`myCPU.sv` 引出后无人读，综合会删），
只能当仿真观察；`miss` 的口径还包含 MMIO（不含 `~uncacheable`），而 `miss_cnt` 不含。
命中率请用 `hit_cnt`/`miss_cnt`（板上 ILA probe7/8），且它们比事件晚一拍。
25 个端口逐根的说明见 [`DCache_接口详解.md`](DCache_接口详解.md)。

## 5. 写回级（WB）

### 5.1 `rtl/WBU.sv` —— 写回选择器

**干什么**：把 ALU 结果 / load 数据 / CSR 读值 / jal 的 link 值收束成**唯一一个写回值**，
写到 `rd`；同时给出 `csrd` 给 CSR 提交。load 的字节/半字选道与符号扩展在这里**再做一次**
（最终值以这里为准）。不产生反压（`ready` 恒 1）。

| 主要输入 | 含义 |
|---|---|
| `MEM_Rdata_in[31:0]`、`funct3_in[2:0]`、`offset_in[1:0]` | load 原料：原始整字 + 宽度 + 地址低 2 位 |
| `Ex_result_in[31:0]`、`rd_value_in[31:0]` | ALU 结果 / link 或 CSR 读值 |
| `csr_wen_in[15:0]`、`R_wen_in`、`mem_ren_in`、`jump_flag_in` | 决定选哪一路 |
| `rd_in[4:0]`、`pc_in[31:0]`、`valid_in` | 目的寄存器 / PC / 有效 |

| 主要输出 | 含义 |
|---|---|
| `rd_value_next[31:0]`、`rd_next[4:0]` | 最终写回值 + 目的寄存器（→ 寄存器堆） |
| `csrd[31:0]`、`csr_wen_next[15:0]` | CSR 写数据 + 位图 |
| `pc_out[31:0]`、`valid_next`、`ready` | 观察口与握手 |

## 6. 全局协同

### 6.1 `rtl/Control.sv` —— 全机控制中枢（最复杂的一个）

**干什么**：四件事——
1. **停拍**：合成 `IFU_stall = load_use_stall | mdu_busy`（`myCPU` 再并上 `dcache_hold`）；
2. **重定向**：`dnpc_flag = intr_take | trap_redirect | bp_mispredict | system_redirect`，
   目标由 `dnpc` 四选一（中断→`mtvec`、异常→`mtvec`、误预测→预测目标纠正、系统指令→各自目标）；
3. **异常优先级**：指令地址非对齐 > 非法指令 > 访存非对齐，给出 `trap_cause` 独热码与 `fault_*`；
4. **前递辅助**：4 深 CSR 影子链做 `csr_rd_fwd`（CSR RAW 前递）、BPU 更新信号、`sys_commit_ok`。

| 主要输入（挑重点） | 含义 |
|---|---|
| `EXU_valid`、`EXU_pred_taken/target`、`branch_flag`、`jump_flag` | 谁要重定向、预测对不对 |
| `mret_flag`、`ecall_flag`、`fence_i_flag`、`intr_pending` | 系统指令与中断 |
| `EXU_illegal_exc`、`EXU_mem_misalign_exc`、`EXU_iaddr_misalign_exc`、`EXU_fault_inst` | 异常源 |
| `mdu_busy`、`mem_stall`、`MEM_m1_ok` | 停拍来源 |
| 各级 `rd`/`valid`/`R_Wen`/`mem_ren` | 冒险与 CSR 前递 |

| 主要输出 | 含义 |
|---|---|
| `IFU_stall`、`load_use_stall` | 前端冻结 / load-use 明细 |
| `dnpc[31:0]`、`dnpc_flag` | 重定向目标 + 单拍请求 |
| `EXU_inst_clear`、`icache_clr` | 清 EX 级 / 清取指（`fence.i`） |
| `trap_take`、`trap_cause[3:0]`、`fault_addr/inst/pc` | 统一异常通道 |
| `bp_update_en/taken/target`、`bp_mispredict`、`bp_hold_exu` | BPU 回写与误预测挡新指令 |
| `csr_rd_fwd[31:0]`、`csr_rd_fwd_en` | CSR 读 RAW 前递值 |
| `sys_commit_ok` | 系统指令"确实会提交"的许可 |

**坑**：`ECALL/MRET` 的重定向脉冲只有一拍，**不能**被 `ready` 门控；`EXU_inst_clear` 与
异常标志清理必须分开（否则死锁）。

### 6.2 `rtl/myCPU.sv` —— CPU 顶层（接线 + 全局协同）

**干什么**：例化 IFU/BPU/IDU/Reg_Stack/EXU/ALU/LSU/WBU/DCache/Data_hazard/Control，
把哈佛两条存储器口引出到顶层（`irom_*` 取指、`perip_*` 访存），并把调试观察量打上
`mark_debug/keep` 给 ILA。

对外三组接口：

| 接口 | 信号 | 含义 |
|---|---|---|
| 时钟/复位 | `cpu_clk`、`cpu_rst` | 单时钟域，复位来自 `reset_sync` |
| 取指（IROM） | `irom_addr`、`irom_en`、`irom_data` | 同步读：T 给地址，T+1 数据有效 |
| 访存（DRAM/MMIO） | `perip_addr`、`perip_wen`、`perip_ren`、`perip_mask`、`perip_wdata`、`perip_rdata` | store 是单拍脉冲；读按 `ren` 门控 |
| 调试 | `debug_wb_*`、`debug_dcache_*_cnt`、`debug_mcause/mepc/mtval`、`debug_dnpc_flag/ready/ifu_pc`、`debug_status`、`debug_mcycle` | 只观察，不参与控制 |

## 8. 板级件（`board/`）

### 8.1 `board/board_top.sv` —— 板级顶层（哈佛 + 三路译码）

**干什么**：接 CPU 的两组存储器口，实现**哈佛结构**：取指只到 IROM 端口 A；数据侧一根总线
三路译码（优先级 `MMIO → IROM 数据窗口 → DRAM`），并接 UART/LED/引导器。

| 译码目标 | 地址范围 | 说明 |
|---|---|---|
| MMIO | `0x1000_0000–0x1000_00FF` | 7 个寄存器：TXDATA/RXDATA/STATUS/LED/… |
| IROM 数据窗口 | `0x0002_0000–0x0002_FFFF` | 走 IROM 端口 B，可读可写（可自改代码） |
| DRAM | `0x0000_0000–0x0001_FFFF` | 低 64 KB 故意留空洞，软件用 `0x1_0000` 以上 |

主要端口：`sys_clk`、`btn_rst_n`、`uart_rx/uart_tx`、`led[6:0]`、`debug_*`（写回信息、命中计数、
异常现场、重定向三线、`debug_status`、`debug_mcycle`、引导状态）。

### 8.2 `board/sync_mem.sv` —— DRAM 模型（1R1W 同步 BRAM）

端口：`addr[31:0]`、`ren`、`rdata[31:0]`、`wen`、`wdata[31:0]`、`mask[1:0]`。
**契约**：T 拍给 `addr` 且 `ren=1`，T+1 才有 `rdata`；`wen` 是单拍脉冲，按 `mask` 合并写；
`reset` 只清 `rdata` 寄存器，**不清存储阵列**。参数 `WORDS`、`READ_ONLY`、`INIT_FILE`。

### 8.3 `board/sync_mem_dp.sv` —— IROM 模型（2R1W 真双口 BRAM，64 KB）

端口 A 只读（取指）：`a_addr/a_ren/a_rdata`；端口 B 读/写（CPU 数据窗口 + 引导器）：
`b_addr/b_ren/b_rdata/b_wen/b_wdata/b_mask`。同拍 A 读 B 写合法；同地址读到旧值。
**综合约束**：三个口必须写在同一个 `always_ff`、同一个时钟里，Vivado 才推成一块 TDP RAM；
拆开会变成两块（面积翻倍）。

### 8.4 `board/reset_sync.sv` —— 复位同步器

异步置位、同步释放的复位同步（按键 → 全机 `cpu_rst`）。

### 8.5 `board/uart_rx.sv` / `board/uart_tx.sv` —— 串口收发（115200 8N1）

| 文件 | 端口 | 说明 |
|---|---|---|
| `uart_rx` | `rx` → `data[7:0]`、`valid`（单拍） | 空闲高；收一个字节给一拍 `valid` |
| `uart_tx` | `data[7:0]`、`send`（单拍） → `tx`、`busy` | `busy=1` 期间不接受新的 `send`；软件轮询 `busy` |

参数 `CLK_FREQ`、`BAUD`；实测 434 拍/位 = 8.68 µs（50 MHz）。

### 8.6 `board/boot_loader.sv` —— 串口引导器（`IROM_BOOT=1` 时生效）

**干什么**：复位后等 UART 上的 magic，收到镜像帧就按 `mem_sel` 写 IROM 或 DRAM，
校验通过后释放 CPU（`busy` 期间 CPU 一直被复位按住）。帧首要求线路**静默 ≥1 ms**（防载荷里
撞上假 magic）。

端口：`rx_data[7:0]`、`rx_valid` → `busy`、`ok`、`err`、`mem_sel`、`mem_we`、`mem_addr[31:0]`
（字地址）、`mem_wdata[31:0]`、`dbg_words[15:0]`。

### 8.7 `board/board_top_ila.sv` / `board_top_vivado.sv` / `tb_board_top.sv`

| 文件 | 状态 | 说明 |
|---|---|---|
| `board_top_ila.sv` | ✅ 被板级外壳例化 | 把 16 组调试量引出给标准 ILA IP；`debug_dead` 是"假负载"，防止综合把调试网优化掉 |
| `board_top_vivado.sv` | ❌ 不用 | 早期 Vivado 顶层（计数器只引 8 位省引脚） |
| `tb_board_top.sv` | 仿真 | 100 MHz + 按键复位的板级 testbench |

## 10. 五条最容易踩的约定（读代码前先记）

1. **同步读**：存储器 T 拍给地址、T+1 才有数据，所以 load 的数据最早 M3 可用；`ren` 必须门控。
2. **store 单拍**：`wen` 只高 1 拍；"发过一次"用 `cpu_adv` 判，不能用 `cpu_en` 电平。
3. **重定向单拍且不得被 `ready` 门控**：`dnpc_flag` 丢了就永久不回来。
4. **`miss` ≠ `miss_cnt`**：MMIO（不可缓存）读也会拉 `miss`，但计数器只数可缓存行。
5. **`reset` 不清存储阵列**：BRAM 的 `reset` 只清 `rdata` 寄存器，DRAM 内容上电是随机的。
