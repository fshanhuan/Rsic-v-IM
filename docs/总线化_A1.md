# A1 总线化：把「顶层四处硬连译码」收成「一个总线模块」

> 目标：让"加一个外设"从**改 4 个地方**变成**改 1 个地方**，同时**逐位保持时序不变**。
> 状态：RTL 完成，板级冒烟测试 4/4 通过；Vivado 综合/时序待验。

---

## 1. 改造前的问题

加一个外设（比如 PWM）要在 `board_top.sv` 里同时动四处，而且每处都要靠人记住"别写错"：

| # | 位置 | 干什么 |
|---|---|---|
| 1 | `board_top.sv:441-442` | `mmio_sel` / `mmio_idx` 译码 |
| 2 | `board_top.sv:546-559` | 读数据三路 mux（MMIO > 代码窗口 > DRAM） |
| 3 | `board_top.sv:582-583` | DRAM 写使能门控 `& ~mmio_sel & ~irom_win_sel` |
| 4 | `board_top.sv:59-113` + xdc | 端口与引脚 |

第 3 处是最危险的：它是靠人脑维持的不变量。漏掉一个 `~irom_win_sel`，一次 `sw 0x2_0040` 会**同时**改掉 IROM 和 DRAM 的第 `0x40` 个字。

## 2. 改造后

新增两个文件：

| 文件 | 职责 |
|---|---|
| `rtl/soc_map.sv` | **地址表的单一来源**：所有基址、容量、片选比较宏、MMIO 寄存器号。不产生逻辑，只有宏。 |
| `board/soc_bus.sv` | 译码 + 片选 + 读数据回选 + 写使能分发。**只做这四件事**。 |

`board_top.sv` 变成：例化总线 + 接从设备。加一个外设 = `soc_map` 加一个基址宏 + `soc_bus` 加一路 `hit`/`we`/`rd` + 例化。

### 2.1 接口

```verilog
soc_bus #(.STRICT_DECODE(1'b0)) u_bus (
    .ren (perip_ren), .wen (perip_wen), .addr (perip_addr), .wdata (perip_wdata), .mask (perip_mask),
    .dram_rdata (dram_rdata), .code_rdata (irom_d_rdata), .mmio_rdata (mmio_rdata),
    .rdata (perip_rdata),
    .hit_dram  (), .hit_code (), .hit_mmio (), .mmio_idx (),
    .re_dram   (), .re_code   (),               // 已按片选门过的读使能
    .we_dram   (), .we_code   (), .we_mmio (),  // 已按片选门过的写使能
    .unmapped  ()                               // 仅严格模式
);
```

### 2.2 三条不变量（写进模块头，改之前必读）

1. **写使能只许有一处判断**：`we_dram = wen & hit_dram` 已经排除了 MMIO 与代码窗口，下游（`sync_mem.wen`）不许再判地址。
2. **读回选必须用 `hit_*`（纯译码），不能用 `sel_*`（含 ren/wen）**。数据在请求的**下一拍**才有效，那时 `ren` 已经撤了——用 `sel_*` 会让所有读回变成 0。这条是本次最容易写错的地方。
3. **`ren` 与 `wen` 必须分开分发**。`perip_ren`（=`dcache_mem_en`）只在读的那一拍为 1，`perip_wen` 只在写的那一拍为 1；合成一个 `req` 会漏掉 store。

## 3. 为什么不是完整 Wishbone / AXI

现在的 CPU 是**固定 1 拍延迟**访存：请求拍给地址，下一拍数据有效。Wishbone 的 `ack` 握手会迫使 LSU 增加一个等待态——而 LSU/DCache 这条路径正是 v14 P4（MMIO 重复读）的现场，且 WNS 只剩 **0.048 ns**。

所以 A1 的定位是**结构性整合，不是协议替换**：

| 方案 | 换外设的改动点 | 时序风险 | 等待态外设 |
|---|---|---|---|
| 现状（四处硬连） | 4 | — | 不支持 |
| **A1（组合译码总线）** | **1–2** | **≈0（未加寄存器）** | 不支持 |
| 完整 Wishbone | 1 | 高（LSU 加等待态） | 支持 |
| AXI4-Lite | 1 | 很高 | 支持 |

等真的出现需要等待态的外设（SD 卡 / 慢速 Flash），再给总线加 `ack` 引脚，那时才有真实需求驱动这次改造。

## 4. 顺带修掉的两处

| 问题 | 改造前 | 改造后 |
|---|---|---|
| **读 MMIO / 代码窗口时 DRAM 也在读**（纯功耗浪费） | `dram.ren = perip_en`，不看地址 | `re_dram = ren & hit_dram` |
| **写使能逻辑散落** | DRAM 的 `.wen` 自己减掉 MMIO/窗口 | `we_*` 全部由总线给出 |

## 5. 验证：`sim/tb_bus.sv`（不需要 C 工具链）

`sim/gen_bus_smoke.py` 手写汇编出一个 36 字的程序，一次踩完四条通路：

| 判据 | 检查方式 | 结果 |
|---|---|---|
| ① DRAM 写/读 | `dram_inst.mem_ram[0x4000] == 0xCAFE_0123` | PASS |
| ② 代码窗口**读** | 程序 `lw` 回 IMEM 第 0 个字并与常量比较 | PASS |
| ③ 代码窗口**写** | `g_irom_rom.irom_inst.mem[0x100] == 0xBEEF_0456` | PASS |
| ④ MMIO | `led == 0x2A` 且 UART 收到 `"OK"` | PASS |

```
[BUS-SMOKE]   [PASS] LED write via we_mmio (0x2A)
[BUS-SMOKE]   [PASS] DRAM write+read via bus (0xCAFE_0123)
[BUS-SMOKE]   [PASS] code-window write via we_code (0xBEEF_0456)
[BUS-SMOKE]   [PASS] UART TXDATA writes -> OK
[BUS-SMOKE] PASS  (4/4)
```

> ② 必须由程序自己比：它验证的正是"读回选用 `hit_*` 而不是 `sel_*`"这条不变量。
> ③ 必须直接查 BRAM 数组：DCache 是写直达，`lw` 读回来会命中缓存，测不出总线写通路。

已接入 `_diag/regress.ps1`（标签 `tb_bus`），成为常驻回归项。

## 6. 改造中发现的既存缺陷

**停机 magic 地址 `0x1000_00F0` 并不是"无副作用"。**

`sw/coremark_port/crt0.S:34-38` 写着：

```c
/* main 返回：写 magic 到 0x1000_00F0，仿真台据此停机。
 * 板上这个地址无副作用（mmio_idx 未定义 → 写被忽略） */
```

但 `mmio_idx = addr[4:2]` 只有 **3 位**：`0xF0 >> 2 = 0x3C`，`0x3C & 7 = 4` → **idx 4 = LED**。

实测：`sw_bus_smoke` 写 magic 后 `led` 从 `0x2A` 变成 `0x5A`（magic 的低 7 位）。

⇒ 两个结论：
1. 那句注释是错的，板上写 magic 会点亮 LED；
2. 这是 `mmio_idx` 只译 3 位的别名问题（`0x1000_0020` 也会撞 `0x1000_0000`），A3 做 CLINT 时必须把 `mmio_idx` 扩到 4 位（`addr[5:2]`）。
