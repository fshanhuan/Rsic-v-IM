# A2 中断子系统：PLIC-lite + `mip.MEIP`

> 一句话：把 `CSR.sv:191` 那句 `assign meip = 1'b0;` 换成一个真正的 8 源中断控制器。
> 状态：RTL 完成，`sim/tb_irq.sv` 3/3 通过，`mcause = 0x8000_000B`（machine external interrupt）。

---

## 1. 改造前

```verilog
// rtl/CSR.sv（改造前）
assign meip = 1'b0;                   // 预留外部中断输入
```

全核**只有 mtime 一个中断源**。后果不是"少一个功能"，而是具体的：

- UART 收字节只能**轮询** `RXSTAT`。RX FIFO 只有 8 深，CPU 在别的循环里待久了就溢出丢字节；
- 上板时"按方向键没反应 / 丢键"就是这条的直接表现（游戏类负载最敏感）；
- 任何未来外设（PWM 到期、DMA 完成、按键）都只能轮询。

---

## 2. 设计

### 2.1 模块

`rtl/plic_lite.sv`（约 90 行）：

```
        src[7:0] ──┐
                   ├─► pending = (pending | src) & ~clr      ← 电平语义
   clr_we[7:0] ────┘
                   ┌─► enabled（软件可读写）
        en_we ─────┘
                       irq = |(pending & enabled)  ──► CSR.mip.MEIP
                       best_id = 最高优先级待处理源号（源号小 = 优先级高）
```

### 2.2 中断源分配

| 源 | 名字 | 含义 | 电平/脉冲 |
|---|---|---|---|
| 0 | `SOC_IRQ_UART_RX` | RX FIFO 非空 | 电平 |
| 1 | `SOC_IRQ_UART_OVF` | RX 溢出过 | 电平 |
| 2 | `SOC_IRQ_TIMER` | 定时器（A3 接 CLINT） | 预留 |
| 3 | `SOC_IRQ_SW` | 软件自触发（写 `0x1000_002C`） | 脉冲 |
| 4–7 | — | 预留 | — |

### 2.3 ★ 为什么是电平，不是边沿

这是本设计最容易做错的一处：

> 用**边沿**置位 pending、claim 清位，会在两个字节之间出现
> "数据还在 FIFO 里、但 pending 已经被清"的**窗口** —— 那个字节从此再也不会触发中断。
>
> **电平**语义保证：只要 FIFO 还非空，claim 之后下一拍它又冒出来。

所以 `pending <= (pending | src) & ~clr`，且 **clear 优先于 set**：claim 那一拍如果源还高高挂着，下拍重新置位，事件不丢。

### 2.4 寄存器（A2 把 `mmio_idx` 从 3 位扩到 4 位）

| 地址 | 名字 | 访问 | 说明 |
|---|---|---|---|
| `0x1000_0020` | `IRQPEND` | RW | 读 = 待处理位图；**写 1 = claim（清这些位）** |
| `0x1000_0024` | `IRQEN` | RW | 使能位图（复位 0） |
| `0x1000_0028` | `IRQID` | RO | 最高优先级的待处理源号（0 = 无） |
| `0x1000_002C` | `IRQSW` | WO | 写 1 → 触发软件源（源 3，自测用） |

> ★ `mmio_idx` 扩宽到 `addr[5:2]` 同时修掉了 A1 发现的**别名缺陷**：
> 原来 3 位时 `0x1000_0020` 会和 `0x1000_0000` 撞车，停机 magic 写 `0x1000_00F0`
> 会点亮 LED（`0xF0>>2 & 7 = 4` = LED）。现在 `0x20` 起是独立寄存器组。

### 2.5 软件用法

```c
#define IRQPEND (*(volatile uint32_t *)0x10000020u)
#define IRQEN   (*(volatile uint32_t *)0x10000024u)
#define IRQID   (*(volatile uint32_t *)0x10000028u)

__attribute__((interrupt("machine"), aligned(4)))
void trap_entry(void) {
    uint32_t id = IRQID;          /* claim：拿最高优先级源号 */
    ...处理...
    IRQPEND = (1u << id);         /* 写 1 清位（处理完） */
}

IRQEN = (1u << 0);                            /* 使能 UART RX */
__asm__ volatile("csrs mie, %0"     ::"r"(1u << 11));   /* MEIE */
__asm__ volatile("csrs mstatus, %0" ::"r"(1u << 3));    /* MIE  */
```

## 3. 验证：`sim/tb_irq.sv`

程序 `sw/irqtest.c` 用**软件源**（源 3）自触发三次，不依赖外部引脚：

```
[IRQ-TEST] uart byte 0 = 0x4f          ← 'O'
[IRQ-TEST] uart byte 1 = 0x4b          ← 'K'
[IRQ-TEST] led=3 nrecv=2 pc=00000200 mcause=8000000b mstatus=00000080
[IRQ-TEST]   [PASS] 3 interrupts taken, claim id = 3 ("OK")
[IRQ-TEST]   [PASS] LED shows interrupt count (3)
[IRQ-TEST]   [PASS] program reached the print (did not hang)
[IRQ-TEST] PASS  (3/3)
```

**`mcause = 0x8000_000B`** 是关键证据：bit31=1（中断）、cause=11（machine external interrupt）。
改造前这个值不可能出现，因为 `meip` 恒 0。

这个测试同时覆盖三段：
1. PLIC-lite 的 pending/enable/claim（MMIO `0x20/0x24/0x28/0x2C`）；
2. `CSR.mip.MEIP` 由外部驱动（原来硬连 0）；
3. Control 的 `intr_take` → 陷入 → `mret` 回程。

## 5. 还没做的

| 项 | 说明 |
|---|---|
| 可编程优先级 / 门限 | 现在是固定优先级（源号小者优先）。标准 PLIC 的 `priority`/`threshold` 刻意不做，文档明确叫 **lite** |
| 中断嵌套 | 处理器不支持嵌套中断（进 handler 时 MIE=0） |
| 源 2（定时器） | 等 A3 的 CLINT 接上 |
| 抢占与尾链 | 不做 |
