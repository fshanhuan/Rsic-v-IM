## 1. 整机结构：功能 5 级、物理 8 级

```
取指(IFU + ICache + Branch_Predictor)
  → 译码(IDU + Reg_Stack + RegisterFile + CSR)
  → 执行(EXU + ALU / MDU_pipelined)
  → 访存(LSU + DCache)
  → 写回(WBU → RegisterFile / CSR)
        ↑ 控制：Control + Data_hazard（前递 / 暂停 / 冲刷 / 重定向 / 中断接收）
```

| 物理级 | 寄存器 | 模块 | 干什么 |
| --- | --- | --- | --- |
| IF | `pc` | `IFU`+`ICache` | 取指、顺序/暂停/重定向/预测跳转 |
| ID1 | `inst/snpc/pc/valid` | `IDU` | 接住原始指令（第 1 拍） |
| ID2 | `inst_d/snpc_d/pc_d/valid_d` | `IDU`+`Control`+`Data_hazard` | 组合译码、读寄存器、前递选择、冒险判定 |
| EX | `*_reg` | `EXU`+`ALU`/`MDU` | 运算、分支判定、跳转目标、预测校验 |
| M1 | `*_reg` | `LSU` | 地址成型、访存控制 |
| M2 | `*_reg_pipe` | `LSU`+`DCache` | 真正发总线、取数据 |
| M3 | `*_reg2` | `LSU` | 访存结果整理（**load 的数据在这一级才出现**） |
| WB | `*_reg` | `WBU`+`RegisterFile`/`CSR` | 结果归一化并写回 |

稳态 1 IPC；一条指令取指→写回约 6~7 拍；遇到同步存储 `hold` 或除法会多几拍。
多出来的三拍对应 `Data_hazard` 的 `MEM(M1) / MEM_PIPE(M2) / MEM2(M3)` 三个前递点。

### 1.1 读代码前必须先懂的 4 条握手约定

1. **`valid`/`ready` 是"寄存输出 + 组合就绪"的握手**：每一级的寄存器只在
   `上游 valid & 本级 ready` 时才更新；`ready` 从下游往上游传（`WBU.ready = 1'b1`）。
2. **`*_next` 是本级寄存后的输出**（送给下一级），`*_last` 是本级从上一级收到的输入。
   例：`EXU.rd_next` = "EX 级里那条指令的 rd"，`EXU.rd` = "IDU 交给 EXU 的 rd"。
3. **`stall` 只冻结寄存器，不产生气泡**：各级在 `valid_last=0` 时是"**保持**"而不是"收气泡"。
   所以**不能**用拉低 `valid` 的办法挡指令（会把上游永远堵死，实测死锁）；
   要作废一条指令，用 `EXU_inst_clear` 把它在 EX 级的控制寄存器清 0。
4. **`hold` 来自同步存储**：`ICache.hold`/`DCache.hold` 在 `myCPU` 里合并成
   `IFU_stall`（冻 PC + 冻 IDU）与 `IFU_mem_stall`（参与 `IFU.valid` 与 `EXU_inst_clear`）。

## 2. 顶层 `myCPU`

### 2.1 对外接口

| 方向 | 信号 | 位宽 | 作用 |
| --- | --- | --- | --- |
| in | `cpu_clk`, `cpu_rst` | 1 | 时钟、高有效同步复位（上板由 `board/reset_sync` 产生） |
| out | `irom_addr` | 32 | 指令地址（由 I-Cache 转发给 IROM/BRAM） |
| in | `irom_data` | 32 | IROM 指令数据 |
| out | `perip_addr/wen/mask/wdata` | — | 数据总线（由 D-Cache 转发给 DRAM/外设） |
| in | `perip_rdata` | 32 | 数据总线读回 |
| out | `debug_wb_have_inst/pc/ena/reg/value` | — | 提交观测口（差分测试探针，也是最省事的上板观察窗） |

### 2.2 顶层信号分组（便于阅读）

- **取指组**：`IFU_pc/IFU_snpc/IFU_inst/IFU_valid`、`IFU_stall/IFU_mem_stall/IFU_stall_ctrl`、`icache_*`。
- **译码组**：`IDU_*`（控制、`add1/add2`、系统标志）、`EXU_rs1_in/EXU_rs2_in`（前递后的操作数）。
- **执行组**：`EXU_*`（`EXU_Ex_result`、`EXU_R_wen`、`EXU_mem_ren`、`EXU_mdu_busy`、`EXU_pred_*`）。
- **访存组**：`LSU_*`（`LSU_Rdata`、`LSU_Ex_result{,_pipe,_wb}`、`LSU_forward_val{_pipe,_wb}`）。
- **写回组**：`WBU_*`（`WBU_rd_value/WBU_rd/WBU_R_wen/WBU_csr_wen`）。
- **控制组**：`dnpc/dnpc_flag`、`EXU_inst_clear`、`load_use_stall`、`bp_*`、`intr_take`、`icache_clr`。

### 2.3 它做了什么"额外"的事（改造重点）

```systemverilog
// 前端总暂停：控制面(load-use/mdu) + 存储侧 hold
assign IFU_stall     = IFU_stall_ctrl | icache_hold | dcache_hold;
// 只含存储侧 hold：参与 IFU.valid 与 EXU_inst_clear
assign IFU_mem_stall = icache_hold | dcache_hold;

// LSU 第一级的"可用结果"：跳转/CSR 用随指令带来的 rd_value，其余用 ALU 结果
assign MEM_forward_val = (LSU_jump_flag | (|LSU_csr_wen)) ? LSU_rd_value : LSU_Ex_result;

// D-Cache 的访问使能取 M2 的 mem_ren（总线地址就是在 M2 出现的）
DCache DCache_inst (.cpu_en(LSU_mem_ren_pipe | lsu_bus_wen), ...);

// WBU 不该被暂停：stall 恒接 0（原来这个端口悬空，是仿真里写回永不发生的原因）
WBU WBU_inst0 (.stall(1'b0), ...);
```

**它在做什么**：顶层不承载任何算术，只做"例化 + 连线 + 命名"以及**三路暂停的合并**。
真正需要理解的是那三路暂停的口径：

| 信号 | 含哪些来源 | 谁用它 |
| --- | --- | --- |
| `IFU_stall_ctrl` | load-use 冒险 ∪ `mdu_busy` | 经 `IFU_stall` 冻 PC/IDU |
| `IFU_mem_stall` | `icache_hold` ∪ `dcache_hold` | `IFU.valid`、`Control.mem_stall` → `EXU_inst_clear` |
| `load_use_stall` | 只含 load-use | `EXU_inst_clear`（**不含 `mdu_busy`**，否则乘除结果会丢） |

**与其他模块的联系**：与片外只有两组总线（`irom_*` 取指、`perip_*` 数据）；
对内把 `ICache`/`DCache` 夹在 `IFU`/`LSU` 与总线之间，把 `Control` 的重定向/暂停广播给前端与执行级。

## 3. 取指前端

### 3.1 `IFU`（取指级）

| 输入 | 作用 |
| --- | --- |
| `clock/reset` | 时钟 / 复位 |
| `dnpc[31:0]`, `dnpc_flag` | 执行级确认的**真实重定向**目标（最高优先级） |
| `pred_taken`, `pred_target[31:0]` | 分支预测给出的**投机跳转** |
| `irom_data[31:0]` | 来自 I-Cache 的指令数据 |
| `stall` | 前端总暂停（load-use / `mdu_busy` / 存储 hold）→ 只冻结 PC |
| `mem_stall` | **只含存储 hold** → 参与 `valid` |
| `inst_valid` | = `ICache.fetch_align`：本拍返回结果是否属于当前 PC 的请求 |
| `ready` | 后级是否可接收（来自 IDU） |

| 输出 | 作用 |
| --- | --- |
| `pc[31:0]` | 当前取指地址（同时是 I-Cache 的 `cpu_addr`） |
| `snpc[31:0]` | `pc+4` |
| `inst[31:0]` | `valid ? irom_data : `NOP``（无效时不把垃圾指令送出去） |
| `valid` | 本拍 `irom_data` 是否确实是当前 PC 的指令 |

**关键信号作用**

- `valid <= inst_valid & ~mem_stall`：当拍判定"命中并交付"。I-Cache 未命中时返回 `` `NOP ``
  且 `hold=1`，所以这个式子等价于"命中"这一个条件。
- `advance_en = valid & ready & inst_valid`：只有确实交付了一条真指令才推进 PC；
  否则 PC 会跑到取指数据前面，让 IDU 收到「下一条地址 + 上一条指令」的错配组合。
- 重定向**不用 `valid` 门控**（只要求当拍确实有一条真指令在交付）：同步存储的停拍
  会让 `valid` 为 0，用 `valid` 去门控会把真实重定向丢掉（实测踩到过）。

**PC 更新优先级**（`IFU.sv`）：
```
reset > dnpc_flag(真实重定向) > pred_taken(预测跳转) > stall(保持) > pc+4
```

**关键代码（`IFU.sv`）**
```systemverilog
assign snpc  = pc + 4;
assign inst  = valid ? irom_data : `NOP;
assign valid = inst_valid & ~mem_stall;          // 当拍判定，见 §3.2 时序
assign advance_en = valid & ready & inst_valid;  // 确实交付了才推进 PC

always_ff @(posedge clock) begin
    if (reset)                           pc <= 32'h0;
    else if (dnpc_flag & ready & inst_valid) pc <= dnpc;        // 真实重定向
    else if (pred_taken_valid & ready)       pc <= pred_target;  // 预测跳转
    else if (stall & valid & ready)          pc <= pc;           // 暂停：保持
    else if (advance_en)                     pc <= snpc;         // 顺序 +4
end
```

**它在做什么**：维护唯一的 PC 状态，并当 ICache 的"取指数据是否可用"翻译成 `valid`。
每个时钟沿只做一件事——决定下一个 PC。

**与其他模块的联系**：`pc/snpc/inst/valid` 直接进 `IDU` 的第一级寄存器；
`pc` 同时是 `ICache.cpu_addr`；`Control` 的 `dnpc/dnpc_flag` 与 `IFU_stall` 控制它；
`Branch_Predictor` 的预测经 `IDU` 寄存后回送到 `pred_taken/pred_target`。

> ⚠️ 改造前的写法是 `assign valid = 1'b1;`（组合读存储时代的假设）。
> 中途还试过"把 `mem_stall` 再打一拍"的版本：同步存储的 hold 与 `fetch_align` 是
> 反相的，延迟一拍后 `valid=1` 恰好全部落在 `stall=1` 的拍上，前端饿死 → 整机在第一次
> 重定向后死锁。结论：**`valid` 必须与取指数据严格同拍**。

### 3.2 `ICache`（指令缓存，直接映射）

| 输入 | 作用 |
| --- | --- |
| `clk/reset` | 时钟 / 复位 |
| `cpu_addr[31:0]` | IFU 的取指地址 |
| `mem_rdata[31:0]` | 来自同步 IROM/BRAM 的指令数据（**读延迟 1 拍**） |

| 输出 | 作用 |
| --- | --- |
| `cpu_rdata[31:0]` | 命中取缓存；未命中/未对齐给 `` `NOP `` |
| `mem_addr[31:0]`, `mem_en` | 发往同步 IROM 的请求（地址 + 使能） |
| `fetch_align` | 本拍返回结果是否属于**当前请求地址**（`resp_valid_r & addr_same_r`） |
| `hit` / `miss` | 本拍访问结果（只有 `fetch_align=1` 时才有意义） |
| `hold` | 本拍无法完成访问，需要前端停一拍重试（`~fetch_align \| miss`） |
| `hit_cnt/miss_cnt[31:0]` | 累计命中/缺失计数（波形与上板观测） |

**组织**：行 = 1 个字（**没有 offset 位**）；`index = addr[INDEX_BITS+1:2]`，
`tag = addr[31:INDEX_BITS+2]`；`INDEX_BITS` 见 `para.sv`（默认 6）。

**同步存储时序契约**（文件头有完整时序图，这里给结论）：

| 拍 | 动作 |
| --- | --- |
| `T` | 呈现请求 A，采样 `cpu_addr_r=A`；这一拍返回的是**旧结果** → `fetch_align=0`、`hold=1` |
| `T+1` | `fetch_align=1` 且 miss → `hold=1`；**同拍**用 A 的 tag/valid + `mem_rdata`(A 的数据) 回填整行 |
| `T+2` | PC 仍是 A，`fetch_align=1` 且 hit → 解除 `hold`，PC 前进 |

**关键代码（`ICache.sv`）**
```systemverilog
assign addr_same_r = (cpu_addr == cpu_addr_r) & cpu_en_r;
assign fetch_align = resp_valid_r & addr_same_r;   // 响应有效 + 地址仍是当前请求
assign hit  = fetch_align && valid[align_index_r] && (tag[align_index_r] == align_tag_r);
assign miss = fetch_align && ~hit;
assign cpu_rdata = hit ? data[align_index_r] : `NOP;   // 未命中不旁路，避免把错数据当指令
assign hold = ~fetch_align | miss;                     // 交给 myCPU 并进 IFU_stall
```

**它在做什么**：在 `IFU` 与同步 IROM 之间做"请求/响应"两拍的握手：把"本拍数据能不能用"
明确成 `fetch_align`，把"要不要停拍重试"明确成 `hold`。它不改变取指语义，
但对 `IFU` 不再是透明的——`IFU.valid` 必须依赖它的 `fetch_align`。

**与其他模块的联系**：`pc → cpu_addr`、`cpu_rdata → IFU.irom_data`、
`fetch_align → IFU.inst_valid`、`hold → myCPU.icache_hold → IFU_stall/IFU_mem_stall`。

### 3.3 `Branch_Predictor`（动态分支预测）

| 输入 | 作用 |
| --- | --- |
| `clk/reset` | 时钟 / 复位 |
| `fetch_pc[31:0]` | IF 级查询地址（= `IFU.pc`） |
| `update_en` | 是否有控制流指令要更新（`Control.bp_update_en`） |
| `update_pc[31:0]` | 更新用 PC |
| `update_index` | **预测时用过的 PHT 索引**（随指令流水携带，保证更新打在同一个表项） |
| `update_taken`, `update_target[31:0]` | 真实方向与真实目标 |
| `update_correct` | 本次预测是否正确 |

| 输出 | 作用 |
| --- | --- |
| `pred_taken` | 预测方向 |
| `pred_target[31:0]` | 预测目标（BTB） |
| `pred_index` | 本次查询用的 PHT 索引（随指令下行） |
| `pred_cnt/hit_cnt/miss_cnt[31:0]` | 预测统计（波形/上板观测） |

**组织**：gshare —— 6 位全局历史 GHR 与 PC 低位异或后索引 64 项 2 位计数器；
另配 64 项 BTB。位宽见 `para.sv`（`BP_INDEX_BITS=6`、`BP_HIST_BITS=6`）。

**它在做什么**：IF 级查表给方向与目标；EX 级用真实结果更新 PHT/BTB。
预测**只在 IF 级使用**（投机跳转），预测错误由 `Control.bp_mispredict` 冲刷纠正。

**与其他模块的联系**：`fetch_pc ← IFU.pc`；预测结果经 `IDU`
（`pred_taken_in/pred_target_in/pred_index_in` → `pt_s1/pt_d`）送到 `EXU`，
再回 `Control` 做校验；更新信号全部来自 `Control`。

## 4. 译码级 `IDU` 与寄存器 / CSR

### 4.1 `IDU`（译码级）

| 输入 | 作用 |
| --- | --- |
| `clock/reset` | 时钟 / 复位 |
| `inst_in[31:0]`, `snpc_in[31:0]`, `pc_in[31:0]` | 来自 IFU 的指令、`pc+4`、`pc` |
| `flush` | 真实重定向（= `dnpc_flag`），把两级译码寄存器清成 `` `NOP `` |
| `stall` | 前端总暂停 → 冻结两级译码寄存器 |
| `EXU_rs1_in`, `EXU_rs2_in` | **`Control` 前递后的操作数**（回灌到译码级） |
| `rd_value/csrd/rd/R_wen/csr_wen` | WBU 的写回值、CSR 读值、写回 rd、写使能 |
| `intr_take`, `intr_pending` | 中断接收与 pending |
| `valid_last` | 上游（IFU）的 `valid` |
| `ready_next` | 下游（EXU）的 `ready` |

| 输出 | 作用 |
| --- | --- |
| `rd_next/rs1/rs2/funct3` | 译码出的 rd / 源寄存器 / `funct3` |
| `add1_value/add2_value[31:0]` | 送 EXU 的 ALU 双输入（已把各族指令统一映射） |
| `rs1_value/rs2_value[31:0]` | 寄存器堆原始读值（给 `Control` 做前递兜底） |
| `alu_opcode[4:0]`, `inv_flag` | ALU 操作码（`bit4=1` 表示 M 扩展）/ 比较取反 |
| `R_wen_next`, `mem_wen`, `mem_ren` | 写回 / 访存控制 |
| `branch_flag`, `jump_flag` | 分支 / 跳转标志 |
| `ecall_flag`, `mret_flag`, `fence_i_flag` | 系统事件（整字比较识别） |
| `csr_wen_next[15:0]`, `csr_addr[11:0]` | CSR 写位图 / CSR 地址 |
| `pc_out`, `branch_pc` | 指令 PC / 分支目标基址（`pc_d + imm`） |
| `pred_taken/pred_target/pred_index` | 随指令下行的预测信息 |
| `valid_next`, `ready_last` | 交给 EXU 的 valid、交给 IFU 的 ready |

**关键信号作用**

- `valid_next = valid_d`：**故意不跟 `stall` 一起拉低**（见 §1.1 第 3 条）。
  被暂停时靠 `ready_last = ready_next && !stall` 把上游挡住，指令留在 IDU 里。
- `add_src1/add_src2`：把不同指令族统一映射成 ALU 的两个输入——
  `is_U0→0`、`is_J/is_U1→pc_d`、其余→`EXU_rs1_in`；`add_src2` 对 R/B 型用
  `EXU_rs2_in`，SYS 的 CSRR 用 `rd_value_next`，其余用立即数。
- `ecall_flag/mret_flag/fence_i_flag`：用整字比较（`32'h00000073` 等）在译码级就识别出来，
  交给 `Control` 统一决定是否重定向。
- `csr_wen_next[15:0]`：每种 CSR 一位的位置映射（见 `para.sv`），
  软件写会在 WB 级真正生效（`CSR.sv`）。

**它在做什么**：两级译码。第一级接住 IFU 的指令，第二级做组合译码；
输出"数据通路控制 + 控制通路事件 + 系统路径入口"三类信息；
内部例化 `Reg_Stack`（读口）、`RegisterFile`、`CSR`。

**与其他模块的联系**：上游 `IFU`；下游 `EXU`（控制 + 操作数）；
与 `Control` 双向（`Control` 回送前递后的操作数，IDU 提供 `IDU_rs1/rs2/valid/mem_ren` 供冒险判定）；
与 `WBU` 相连（写回值读口）。

### 4.2 `Reg_Stack` + `RegisterFile` + `CSR`

| 模块 | 重要输入 | 重要输出 | 作用 |
| --- | --- | --- | --- |
| `RegisterFile` | WBU 的 `rd/rd_value/R_wen`、`rs1/rs2` 读地址、`clock/reset` | `rs1_value/rs2_value` | 32×32 寄存器堆：组合读、时钟沿写、`rd!=0` 才写、复位清零 |
| `Reg_Stack` | `rs1/rs2`、写回通道 | `rs1_value/rs2_value` | 寄存器堆读口 + 前递选择值的出口 |
| `CSR` | `pc`、`ecall_flag`、`mret_flag`、`intr_take`、`csrd`、`csr_wen[15:0]` | `mepc/mcause/mstatus/mtvec/mie/mip/mscratch/mtime/mtimecmp` 等 `*_out`、`intr_pending` | 机器模式 CSR 组 |

**`CSR` 关键信号作用**

- `ecall_flag` → 写 `mcause/mepc`；`mret_flag` → 从 `mepc` 返回并恢复 `mstatus`；
  `intr_take` → 走同一个异常入口（`Control.dnpc` 取 `mtvec_out`）。
- `intr_pending = mstatus.MIE & |(mie & mip)`：只有全局使能打开、且某个中断源
  既使能又挂起时才为 1。`Control` 只在 `intr_safe` 成立时才接受中断（见 §8.2），
  以保证**精确中断**——`mepc` 指向真正被打断的那条指令。

**`RegisterFile` 改造点**：原来没有复位分支，仿真里 `rf[0]`(x0) 初值是 `x`
（4 态仿真才暴露，2 态工具看不见），已补：
```systemverilog
if (reset) for (int i = 0; i < 32; i++) rf[i] <= 32'b0;   // 上板改造：补上复位分支
```

### 4.3 立即数生成（`IDU` 内）

`IDU` 里按 `opcode` 选出 `imm_I/imm_S/imm_B/imm_U/imm_J` 之一，
再由 `add_src1/add_src2` 与 `branch_pc = pc_d + imm` 消费：
分支用 `pc_d+imm`（`branch_pc`），跳转用 `add_src1=pc_d`、`add_src2=imm`
（在 EXU 里相加得到目标）。U 型指令走"`add_src1=0`、`add_src2=imm`"的直通路径。

## 5. 执行级 `EXU`

| 输入 | 作用 |
| --- | --- |
| `clock/reset` | 时钟 / 复位 |
| `EXU_inst_clr` | **清空本级控制寄存器**（重定向 / 存储停拍 / load-use，见 §8.2） |
| `add1`, `add2[31:0]` | ALU 双输入（来自 IDU 的 `add1_value/add2_value`） |
| `rs2_value[31:0]` | 前递后的 rs2（给 store 数据用） |
| `rd_value[31:0]` | 随指令带来的"直接写回值"（跳转 `snpc` / CSR 读值） |
| `alu_opcode[4:0]`, `inv_flag` | ALU 操作码（`bit4=1`→MDU）/ 比较取反 |
| `rd[4:0]`, `funct3[2:0]`, `pc[31:0]` | 目标寄存器 / 访存宽度 / 指令 PC |
| `R_wen`, `mem_wen`, `mem_ren`, `csr_wen[15:0]` | 写回 / 访存 / CSR 控制 |
| `branch_flag`, `jump_flag`, `branch_pc[31:0]` | 分支/跳转标志与分支目标基址 |
| `fetch_i_flag` | `fence.i` 标志 |
| `pred_taken_in`, `pred_target_in[31:0]`, `pred_index_in` | 随指令带来的预测信息 |
| `valid_last`, `ready_next` | 上游 valid / 下游 ready |

| 输出 | 作用 |
| --- | --- |
| `EX_result[31:0]` | 运算结果；**最低位是分支条件归一化结果**（`exec_res[0] ^ inv_flag_reg`） |
| `*_next`（`rd/R_wen/mem_wen/mem_ren/csr_wen/funct3/rs2_value/rd_value/jump_flag/branch_flag/branch_pc/fetch_i_flag/pred_*`） | 送给 LSU 的控制与数据 |
| `pc_out[31:0]` | 本级指令的 PC（给 Control 算重定向目标） |
| `valid_next`, `ready_last` | 交给 LSU 的 valid / 交给 IDU 的 ready |
| `mdu_busy`, `mdu_done` | MDU 忙 / 本拍结果有效 |

**关键信号作用**

- `mdu_start = (mdu_state == MDU_IDLE) & alu_opcode_reg[4]`：用**寄存器**版的
  `alu_opcode` 触发。因为 MDU 的操作数是 `add1_reg/add2_reg`，用输入端口会让状态机
  比操作数早一拍进入 WAIT，`done` 永远不来（实测死锁）。
- `mdu_stall = (state == WAIT) | (state == DONE)`：`DONE` 也要冻一拍，
  因为 LSU 是**下一个时钟沿**才取走 `EX_result`，这一拍解冻会让同一条 M 指令被重复发射。
- `valid_next` 的更新条件（改造后的关键）：
  `reset > (mdu_stall | ~ready_next) 冻结 > (EXU_inst_clr) 清 0 > 正常置 1 > 否则 0`。
  **`~ready_next` 冻结是新增的**：同步存储带来 `mem_hold` 时 `ready_next(=LSU_ready)` 为 0，
  原来会走到最后的 `else` 把 `valid_next` 清 0，而数据/控制寄存器是冻结保持的 →
  这条指令带着 `valid=0` 进 LSU，写回被 `WBU.R_wen_next = R_wen_reg & valid_reg` 掐掉
  （实测：`add x7,x6,x2` 算出正确的 `0x11` 却写不进 x7）。
- 控制寄存器与 `valid` 是**两个 `always_ff`**：`valid_last=0` 时控制寄存器保持、
  `valid` 会变——所以 `Control` 里所有来自 EXU 的"控制事实"都必须用 `EXU_valid` 限定（见 §8.2）。

**关键代码（`EXU.sv`）**
```systemverilog
assign mdu_start = (mdu_state == MDU_IDLE) & alu_opcode_reg[4];
assign mdu_stall = (mdu_state == MDU_WAIT) | (mdu_state == MDU_DONE);
assign exec_res  = alu_opcode_reg[4] ? mdu_res_reg : alu_res;
assign EX_result = {exec_res[31:1], exec_res[0] ^ inv_flag_reg};   // 低位=分支条件
assign ready_last = ready_next & ~mdu_stall;

always_ff @(posedge clock) begin
    if (reset)                              valid_next <= 1'b0;
    else if (mdu_stall | ~ready_next)       valid_next <= valid_next;   // 冻住（同数据寄存器口径）
    else if (ready_last & valid_last & EXU_inst_clr) valid_next <= 1'b0;
    else if (ready_last & valid_last)       valid_next <= 1'b1;
    else                                    valid_next <= 1'b0;
end
```

**它在做什么**：一拍完成"算结果 + 判分支 + 算跳转目标 + 准备预测校验信息"，
并在 `mdu_busy` 期间冻结自己等乘除结果。

**与其他模块的联系**：上游 `IDU`（控制 + 操作数）与 `Control`（清空）；
下游 `LSU`（`EX_result` + 全套控制 + `EXU_valid`）；与 MDU 握手；
把 `EX_result/pred_*/pc_out` 送回 `Control` 做重定向与预测校验。

### 5.1 `ALU`（整数运算）

| 输入 | 作用 |
| --- | --- |
| `d1[31:0]`, `d2[31:0]` | 双操作数 |
| `choice[4:0]` | 操作码；`choice[4]=1` 表示 M 扩展（实际由 EXU 选 MDU 结果） |

| 输出 | 作用 |
| --- | --- |
| `res[31:0]` | 运算结果 |

纯组合。加减复用 `add.sv` 小单元（`choose_add_sub/add_1/add_2/add_2_inv → result`）。

### 5.2 `MDU` 与 `MDU_pipelined`（RV32M 乘除法）

| 版本 | 重要输入 | 重要输出 | 特点 |
| --- | --- | --- | --- |
| `MDU.sv`（原版） | `d1/d2/op` | `res` | 单拍**纯组合**：3 个 32×32 乘法器 + 32 级恢复余数除法链。已不参与上板路径，保留对照 |
| `experimental/MDU_pipelined.sv`（上板用） | `start/d1/d2/op` | `res/busy/done` | 乘法 1 拍；除法多拍，用 `busy` 冻结流水 |

**规模对比**（`syn/synth_report.md`）：单拍组合版 **2150 LC / 419 CARRY4** →
流水化版 **407 LC / 81 CARRY4**（约 1/5），DSP48E1 都是 12。
流水化版已用 **4968 条向量**（968 边界 + 4000 随机，覆盖除零、`INT_MIN/-1` 溢出、符号回正）
做过模块级验证，并已接入 `EXU`。

**与其他模块的联系**：只在 `EXU` 内部例化；对外表现为 `EX_result` 与 `EXU_mdu_busy`
（后者同时冻结前端与访存流水）。

## 6. 访存级 `LSU` 与 `DCache`

### 6.1 `LSU`

| 输入 | 作用 |
| --- | --- |
| `Ex_result[31:0]` | 访存地址（EXU 算出的地址） |
| `mem_ren`, `mem_wen`, `R_wen`, `csr_wen[15:0]` | 访存与写回控制 |
| `rd/funct3/rs2_value/rd_value/pc/jump_flag` | 随指令往下传的信息 |
| `rdata[31:0]` | 来自 `DCache` 的读回数据 |
| `mem_hold` | D-Cache 要求重试（未命中/同步读未完成） |
| `mdu_busy` | MDU 迭代中 |
| `valid_last`, `ready_next` | 上游 valid / 下游 ready |

| 输出 | 作用 |
| --- | --- |
| `addr/wen/wdata/mask` | 给 `DCache` 的总线请求（**地址取 M2 的地址寄存器**，低 2 位强制 0） |
| `Ex_result_next/rd_next/mem_ren_next/R_wen_next/valid_next`, `*_pipe`, `*_wb` | 三级随指令下传的信息 |
| `LSU_Rdata` / `LSU_Rdata_raw` | 按 `funct3` 扩展后的数据 / 原始数据 |
| `forward_val_pipe`(M2) / `forward_val_wb`(M3) | 三级"可用结果"给 `Control` 做前递 |

**三级流水的语义**（这是本机最容易读错的地方）：

| 级 | 寄存器 | 对 load 而言它是什么 |
| --- | --- | --- |
| M1 | `*_reg`（`Ex_result_fwd_reg`） | **地址** |
| M2 | `*_reg_pipe` | **还是地址**（总线请求在这一拍发出去） |
| M3 | `*_reg2` + `rdata_reg2` | **数据**（`forward_val_wb` 在这一级把 load 的结果替换成 `rdata_wb2`） |

**关键信号作用**

- `lsu_freeze = mem_hold | mdu_busy`，`ready_last = ready_next & ~lsu_freeze`：
  整条访存流水**同步冻结**。必须整条一起冻——否则 `mem_ren_reg_pipe` 会被推走、
  `DCache.cpu_en` 的组合来源跟着变，`hold` 自己就把自己解掉了。
- `Ex_result_addr_reg` 与 `Ex_result_fwd_reg` 分开存：前者专门驱动总线地址，
  后者用于前递，便于用 `max_fanout` 属性控制扇出。
- `forward_val_wb = jump|csr ? rd_value_reg2 : (mem_ren_reg2 ? rdata_wb2 : Ex_result_fwd_reg2)`：
  **load 的数据只在这一级出现**。

**与其他模块的联系**：上游 `EXU`；下游 `DCache`（`addr/wen/wdata/mask ↔ rdata`）
与 `WBU`（`*_wb`）；把 M1/M2/M3 三级可用值送 `Control`
（`MEM_forward_val` / `LSU_forward_val_pipe` / `LSU_forward_val_wb`）。

### 6.2 `DCache`（数据缓存，写直达）

| 输入 | 作用 |
| --- | --- |
| `clk/reset` | 时钟 / 复位 |
| `cpu_en` | 访问使能（`LSU_mem_ren_pipe \| lsu_bus_wen`） |
| `cpu_wen`, `cpu_addr[31:0]`, `cpu_wdata[31:0]`, `cpu_mask[1:0]` | 写使能 / 地址 / 写数据 / 字节掩码 |
| `mem_rdata[31:0]` | 同步 DRAM 的读回数据（读延迟 1 拍） |

| 输出 | 作用 |
| --- | --- |
| `cpu_rdata[31:0]` | 命中的数据 |
| `mem_addr/mem_en/mem_wen/mem_wdata/mem_mask` | 发往 DRAM/外设的请求 |
| `hit` / `miss` | 访问结果 |
| `hold` | 本拍没拿到数据，请 LSU 停一拍重试 |
| `hit_cnt/miss_cnt[31:0]` | 命中/缺失计数 |

**关键信号作用**

- `cpu_en` 取 **M2** 的 `mem_ren_pipe`：总线地址就是在 M2 出现的。
- **store 单拍写脉冲**：同步 DRAM 的写使能会保持多拍，直接透传会重复写，
  因此在内部把 store 请求寄存成一拍脉冲（测试台有 `write-once` 专项检查）。
- **MMIO/uncacheable 直通**：地址落在外设区间时不走 tag 数组，直接发 `mem_*`，
  保证能读到外设的"每次不同"的值、也能写到外设。

**与其他模块的联系**：与 `LSU` 用 `cpu_*` 握手、与片外 DRAM/外设用 `mem_*`；
`hold` 上报到 `myCPU` 变成 `dcache_hold`，进而参与 `IFU_stall`/`IFU_mem_stall`/`lsu_freeze`。

## 7. 写回级 `WBU`

| 输入 | 作用 |
| --- | --- |
| `MEM_Rdata_in[31:0]`, `funct3_in[2:0]` | load 数据与宽度 |
| `Ex_result_in[31:0]`, `rd_value_in[31:0]` | ALU 结果 / 随指令带来的直接写回值 |
| `rd_in[4:0]`, `R_wen_in`, `csr_wen_in[15:0]`, `mem_ren_in`, `jump_flag_in`, `pc_in` | 写回控制与 PC |
| `valid_in` | 上游有效 |
| `stall` | **恒接 `1'b0`**（写回级不该被暂停） |

| 输出 | 作用 |
| --- | --- |
| `rd_value_next[31:0]` | 最终写回值（四选一） |
| `rd_next[4:0]`, `R_wen_next` | 目标寄存器与写使能（`= R_wen_reg & valid_reg`） |
| `csr_wen_next[15:0]`, `csrd[31:0]` | CSR 写位图与写数据（`= Ex_result_reg`） |
| `pc_out[31:0]`, `valid_next` | 提交 PC 与 valid（调试口用） |
| `ready` | 恒 1 |

**关键信号作用**

- `wb_sel_jmp_csr = jump_flag_reg | (|csr_wen_reg)`：跳转/系统指令直接用随指令带来的
  `rd_value_reg`（`snpc` 或 CSR 读值）。
- `rd_value_next = wb_sel_jmp_csr ? rd_value_reg : (mem_ren_reg ? rdata_wb : Ex_result_reg)`：
  load 用访存数据，其余用 ALU 结果——**四种来源在这里收敛**。
- `R_wen_next = R_wen_reg & valid_reg`：`valid` 必须参与，这是"被清空的指令不写寄存器"
  的最后一道闸门（也正是 §5 那个 `valid` 掉拍 bug 的暴露点）。

**它在做什么**：把 ALU 结果 / load 数据 / 跳转返回地址 / CSR 读值统一成 `rd_value_next`，
并给出最终的写使能与 CSR 写信号。

**与其他模块的联系**：上游 `LSU`；下游 `RegisterFile`（写口）、`CSR`（写 CSR）、
`IDU`（写回值读口 `rd_value/csrd/R_wen/csr_wen`）、以及 `debug_wb_*` 观测口。

## 8. 冒险处理：`Data_hazard` 与 `Control`

### 8.1 `Data_hazard`（前递仲裁器）

| 输入 | 作用 |
| --- | --- |
| `IDU_rs1/IDU_rs2[4:0]` | 消费者要用的源寄存器 |
| `EXU_rd/MEM_rd/MEM_PIPE_rd/MEM2_rd/WB_rd[4:0]` | 各级写者（含 M1/M2/M3/WB） |
| `EXU_valid/MEM_valid/MEM_PIPE_valid/MEM2_valid/WB_valid` | 各级有效 |
| `EXU_R_Wen/MEM_R_Wen/MEM_PIPE_R_Wen/MEM2_R_Wen/WB_R_Wen` | 各级写使能 |
| `MEM_mem_ren`, `EXU_mem_ren` | 该级是不是 load（是的话当拍 `EX_result` 是地址，不能当前递源） |

| 输出 | 作用 |
| --- | --- |
| `IDU_rs1_choice[2:0]` / `IDU_rs2_choice[2:0]` | 前递来源编码 |

**编码与优先级**（越新的写者越优先）：

| 编码 | 来源 | 值取自 |
| --- | --- | --- |
| `3'b001` | EXU | `Ex_result`（**仅当 `~EXU_mem_ren`**） |
| `3'b010` | MEM(M1) | `MEM_forward_val`（**仅当 `~MEM_mem_ren`**） |
| `3'b101` | MEM_PIPE(M2) | `LSU_forward_val_pipe`（对 load 仍是地址，所以此时靠暂停挡住） |
| `3'b011` | MEM2(M3) | `LSU_forward_val_wb`（**load 的数据在这里**） |
| `3'b100` | WB | `WBU_rd_value` |
| `3'b000` | 都不用 | `IDU_rs1_value`/`IDU_rs2_value`（寄存器堆原值） |

**关键信号作用**

- `exu_hit_rs1 = EXU_R_Wen && ~EXU_mem_ren && (EXU_rd == IDU_rs1) && (EXU_rd != 0)`：
  **`~EXU_mem_ren` 是改造新增的关键限定**——EXU 级若是 load，当拍 `EX_result` 是**地址**，
  不能当前递源。原来只看 `R_Wen` 且优先级最高，`lw` 后紧跟的 `add` 会拿到基址
  （实测 `0x1005` = 地址 + 5）。
- `mem_hit_*`：`MEM_mem_ren ? 3'b000 : 3'b010`——M1 若是 load，数据同样还没到，
  返回 000 交给上层停顿。

**与其他模块的联系**：只在 `Control` 内部例化（`Data_hazard_inst`）；
输出编码由 `Control` 翻译成真正的数据值。它**不搬数据**，只出编码。

### 8.2 `Control`（全局协同核心）

| 输入（关键） | 作用 |
| --- | --- |
| `branch_pc`, `Ex_result`, `EXU_pc`, `EXU_pred_taken/pred_target` | EX 级事实 |
| `IDU_rs1/rs2`, `IDU_rs1_value/rs2_value`, `IDU_valid` | 译码级消费者信息 |
| 各级 `*_rd` / `*_valid` / `*_R_Wen` / `*_mem_ren` | 冒险判定与前递 |
| `MEM_Ex_result` / `MEM_PIPE_Ex_result` / `MEM2_Ex_result` | 三级可用值 |
| `WB_rd_value/WB_rd/WB_R_Wen/WB_valid` | 写回级 |
| `branch_flag/jump_flag/mret_flag/ecall_flag/fence_i_flag` | 控制流与系统事件 |
| `intr_pending`, `mdu_busy`, `mem_stall` | 中断、MDU 忙、存储停拍 |
| `mtvec_out`, `mepc_out` | 异常入口与返回地址 |

| 输出 | 作用 |
| --- | --- |
| `IFU_stall` | 前端总暂停（load-use ∪ `mdu_busy`） |
| `load_use_stall` | **只含 load-use**（给 `EXU_inst_clear` 用，不含 `mdu_busy`） |
| `EXU_rs1_in/EXU_rs2_in[31:0]` | 前递后的操作数（回灌 `IDU`） |
| `EXU_inst_clear` | 清空 EX 级刚收下的那条指令的控制位 |
| `icache_clr` | `fence.i` 清 I-Cache |
| `dnpc[31:0]`, `dnpc_flag` | 重定向目标与请求 |
| `intr_take` | 本拍接受中断 |
| `bp_update_en/bp_update_taken/bp_update_target/bp_mispredict` | 预测器更新与预测校验 |

**关键信号作用**

- `EXU_ctrl_valid = EXU_valid`（新增）：EXU 的 `valid` 与控制寄存器由两个 `always_ff` 维护，
  `valid=0` 时控制寄存器可能还是上一条指令的残留值。不限定就会出现
  "EXU 空、但 `jump_flag/pred_*` 还在产生重定向" → 无休止重定向 → 死循环。
- `branch_taken = branch_flag & Ex_result[0] & ~mdu_busy & EXU_ctrl_valid`：
  分支条件在 EXU 已归一化到 `EX_result[0]`；MDU 忙期寄存的是刚发射的 M 指令，
  残留标志不可信，一律屏蔽。
- `bp_mispredict`（判错）：方向或目标不符即判错，但被
  `intr_take | system_redirect | mem_stall` 屏蔽（这些事件有自己的重定向通道，
  且 `mem_stall` 期间 EXU 被冻住，预测校验要等 hold 结束），再经 `bp_redirect_pending`
  **一次性化**——一次预测错误只重定向一次（详见 §9.2）。
- `EXU_inst_clear = intr_take | bp_mispredict | mem_stall | load_use_stall`：
  作用是**把刚被 EXU 收下的那条指令的控制位清 0**（变无副作用的空操作）。
  **不含 `system_redirect`**：`ecall/mret/fence.i` 自己必须流到 WB，它们引发的冲刷
  只冲掉排在后面的错路径指令（由 `dnpc_flag`→`IDU.flush` 完成）。
- load-use 判定：`exu_load_use` / `mem_load_use` / `pipe_load_use` 分别是
  "EXU / M1 / M2 里是 load，且它的 `rd` 与 IDU 里那条指令的 `rs` 相同"。
  三者**不乘 `IDU_valid`**：IDU 空时 `inst_d` 是 `` `NOP ``（`rs1=rs2=0`），
  而判定要求 `rd != 0`，不会误判；乘上 `IDU_valid` 会让暂停条件在同一拍自己消失。
  命中任一即 `load_use_stall`；到 **M3** 时三个条件全为 0，由 `3'b011` 前递直接给数据。
- `intr_safe = IDU_valid & ~(branch_flag|jump_flag|fence_i_flag) & ~mret_flag & ~ecall_flag
  & ~IFU_stall & ~mdu_busy`：保证精确中断（`mepc` 指向真正被打断的指令），
  `intr_take = intr_pending & intr_safe`。
- `dnpc` 优先级：`intr_take > bp_mispredict > system_redirect`
  （中断取 `mtvec`；判错取真实目标或 `EXU_pc+4`；`mret` 取 `mepc`，`ecall`/异常取 `mtvec`）。

**关键代码（`Control.sv`）**
```systemverilog
assign load_use_stall = exu_load_use | mem_load_use | pipe_load_use;
assign IFU_stall      = load_use_stall | mdu_busy;
assign EXU_inst_clear = intr_take | bp_mispredict | mem_stall | load_use_stall;

assign bp_mispredict_raw = EXU_ctrl_valid & ~(intr_take | system_redirect | mem_stall) &
                           ((actual_taken != EXU_pred_taken) ||
                            (actual_taken && (actual_target != EXU_pred_target)));
assign bp_mispredict = bp_mispredict_raw & ~bp_redirect_pending;   // 一次性脉冲

// 前递编码 -> 真正的数据值
assign EXU_rs1_in = (IDU_rs1_choice == 3'b001) ? Ex_result :
                    (IDU_rs1_choice == 3'b010) ? MEM_Ex_result :
                    (IDU_rs1_choice == 3'b101) ? MEM_PIPE_Ex_result :
                    (IDU_rs1_choice == 3'b011) ? MEM2_Ex_result :
                    (IDU_rs1_choice == 3'b100) ? WB_rd_value : IDU_rs1_value;
```

**它在做什么**：三件事——① 收束所有会改写 PC 的事件生成 `dnpc/dnpc_flag`；
② 识别 load-use 冒险决定前端冻结与执行级清空；③ 把前递编码翻译成真正的数据值。

**与其他模块的联系**：几乎所有模块都接到它——`IFU` 拿 `dnpc/dnpc_flag`、
`IDU` 拿前递操作数与 `flush`、`EXU` 拿清空、`Branch_Predictor` 拿更新、
`CSR` 拿 `intr_take`、`ICache` 拿 `icache_clr`。

## 9. 上板改造：同步存储带来的三个必知机制

### 9.1 为什么 load 的数据只在 M3 才可前递

`LSU` 把同一份 `Ex_result` 存了三份，而"数据"只出现在最后一份：

| 级 | 对 load 而言 | `Control` 里的对应值 | 能不能前递 |
| --- | --- | --- | --- |
| M1 | 地址 | `MEM_forward_val`（`LSU_mem_ren=1` 时返回 000） | ✗ 必须停顿 |
| M2 | 还是地址 | `LSU_forward_val_pipe`（编码 `3'b101`） | ✗（暂停挡住） |
| M3 | **数据**（`rdata_wb2`） | `LSU_forward_val_wb`（编码 `3'b011`） | ✓ |
| WB | 数据 | `WBU_rd_value`（编码 `3'b100`） | ✓ |

所以 `Data_hazard` 的 `3'b101`(M2) 对 load **不是有效前递源**；负载数据唯一正确来源
是 M3 的 `forward_val_wb`（或更晚的 WB）。load-use 暂停因此必须覆盖
"load 在 EXU / M1 / M2"这三级，到 M3 自然放开、由 `3'b011` 送数据。

### 9.2 重定向必须"一次性"，而且不能清掉系统指令自己

- `bp_mispredict` 原来是**电平**信号：只要那条被判错的指令还停在 EXU 里就一直为 1。
  上板后引入存储 `hold`，EXU 可能被冻住好几拍，于是变成**连环重定向**——
  重定向目标那条指令（例如 `ecall`）永远进不了流水。
  现象：`IFU_pc` 反复回到目标地址、`EXU_valid/LSU_valid` 恒 0、`mepc/mcause` 恒 0。
  修法：`bp_redirect_pending` 标志，一次判错只给一个重定向脉冲。
- `EXU_inst_clear` **不含 `system_redirect`**：`ecall` 被收进 EXU 的同一拍，
  如果被当成"要清掉的指令"，它的 `csr_wen` 会被清 0 → 异常永远不产生。
  `ecall/mret/fence.i` 必须自己流到 WB；它们引发的冲刷只针对后面的错路径指令。
- 所有来自 EXU 的控制事实（`branch_flag/jump_flag/pred_*`）都要用 `EXU_valid` 限定。

### 9.2b 第二轮修复（独立验证发现的 7 个缺陷，机制上必须知道的 4 条）

> 完整证据、原始输出与复现命令见仓库根目录 [`验证报告_独立复核.md`](../../验证报告_独立复核.md)。

1. **load 的字节/半字必须按 `addr[1:0]` 选道**（`LSU.sv` + `WBU.sv`）。
   读口返回的是"该地址所在字"的**原始整字**，偏移只在地址里。两处都做抽取
   （LSU 用于前递观察、WBU 用于最终写回），所以两处都要选道，否则 `lb/lh/lbu/lhu`
   永远读到第 0 字节。
2. **DCache 读握手的契约是"hold 撤销的那一拍 `cpu_rdata` 就是当前地址的数据"**
   （`DCache.sv`）。`hold` 不能在"刚发出读"那一拍就撤销（数据还没回来），
   否则 LSU 会把总线残留值/`x` 锁进 `rdata_reg2`。
   判定用**当前地址**组合算 `hit_now`，加上"本拍返回的是当前地址的读"`resp_for_now`。
3. **前递仲裁的口径必须与暂停口径一致**（`Data_hazard.sv`）。
   `Control` 的 `mem_load_use/pipe_load_use` 要求 `MEM_valid/MEM_PIPE_valid`，
   那么 `Data_hazard` 的 `mem_hit/pipe_hit` 也必须检查 `valid`，**并且把 load 排除出
   MEM/MEM_PIPE 级**（load 的数据固定在 MEM2 前递）。否则会出现"valid=0 但 rd 命中"
   的错配状态把 MEM2 的可用数据挡掉 —— 消费者的 `sw` 会写进寄存器堆里的旧值。
4. **误预测判定只能被"推后"，不能被丢弃**（`Control.sv` + `IFU.sv` + `EXU.sv`）。
   - `hold` 期间 IFU 的 `ready`(=IDU_ready) 为 0，此刻发出的重定向会被 **IFU 丢掉**，
     所以判定要连同**方向与目标**挂起（`bp_misp_pend/bp_pend_taken/bp_pend_target`），
     等 `~mem_stall` 补发一次；挂起值**优先**于当拍新判定（先来先服务）。
   - 挂起期间必须**挡住 EXU 接收新指令**（`bp_hold_exu`）：否则错路径那条会赶在
     补发之前进入 EX 并被下游采走、提交。注意只挡"接收"，不挡"清空"——
     正在 EX 里那条被判错的跳转仍要在重定向当拍正常交给 LSU（`jal` 的 link 靠这一拍）。
   - `IFU` 的**投机拨 PC** 必须和"本拍确实接收了这条指令"用同一个条件
     （`valid & ready & inst_valid & ~stall`）。否则会出现"预测说跳了、PC 没跳"，
     而 EXU 侧比较 `actual == pred` 认为没判错 —— 分支指令被丢掉却无人纠正。
   - `EXU_inst_clear` 里的 `mem_stall` 项**不能作用于分支/跳转**：那一条的理由是
     "load 取回的数据无效、要作废重放"，对不依赖访存数据的分支不成立，
     清掉它等于把它还没做的判定一起扔掉。
5. **多拍 MDU 的握手要"一次发射 + 自己的结果"**（`EXU.sv`）。
   `mdu_start` 必须带"这条指令已发射过"标志（`mdu_issued`），否则结果窗口结束、
   回到 IDLE 那一拍会**用还没被换掉的旧操作码再发射一次**（操作数此时已换成下一条），
   于是上一条的运算结果被当成下一条指令的结果。
   冻结条件也要改成"EX 级是 M 指令、且**它自己的**结果还没锁存"（`mdu_res_vld`），
   并且让 LSU 用同一口径冻结（`mdu_busy = mdu_stall`）。
6. **EXU 级前递对 jump/CSR 要取 `rd_value`**（`Control.sv` + `myCPU.sv`）。
   `Ex_result` 对 jump 是**跳转目标地址**，写进 rd 的是 link；两者不能混。
   MEM/PIPE/WB 三级本来就是这么做的（`MEM_forward_val`），EXU 级补齐即可。

### 9.3 "拉低 valid 挡指令"会死锁

v9 各级的寄存器更新条件是 `valid_last & ready_next`，`valid_last=0` 的含义是
"上游没给新指令" → **保持**，不是"收一个气泡"。因此：

- 想让 IDU 把消费者挡住，如果拉低 `IDU.valid_next`：EXU 永远保持上一条（load），
  `exu_load_use` 恒 1、`IFU_stall` 恒 1 → **死锁**（实测）。
- v9 原本的正确思路是：消费者被 EXU 提前收下 → 控制位清 0（`EXU_inst_clear` 含
  `load_use_stall`）→ IDU 因被 `stall` 冻结仍持有这条指令 → 暂停解除后再送一次，
  这一次 load 已经走到 M3，由 `3'b011` 给出正确数据。

> 另外：`mdu_busy` 只能并进 `IFU_stall`，**不能**并进"给 IDU 灌气泡"的那一路，
> 否则会打断 M 指令自己的向后 `valid`，乘除结果直接丢失
> （实测 `prog_mul` 从全过变成 1 处不符）。

## 10. 典型指令走查

### 10.1 `add x3, x1, x2`（无冒险）

`IFU` 取指 → `IDU` 译码（`add_src1=EXU_rs1_in`，`add_src2=EXU_rs2_in`）→ `EXU` 相加出
`EX_result` → `LSU` 只做搬运（`mem_ren/mem_wen` 都是 0）→ `WBU` 选 `Ex_result_reg` → 写 `x3`。

### 10.2 `lw x6, 0(x1)`（同步存储：miss → 回填 → 命中）

1. `EXU` 算出地址 `0x1000`，`mem_ren=1`；
2. M2 把地址发到 `DCache` → `DCache` 未命中 → `hold=1` → `lsu_freeze=1`，整条访存流水冻结；
3. 同步 DRAM 一拍后给数据 → `rdata` 有效、`hold` 撤 → 数据在 M2→M3 的沿被 `rdata_reg2` 记下；
4. M3 的 `forward_val_wb` 把 load 的结果替换成 `rdata_wb2` → `WBU` 选它写回。

### 10.3 `lw x6, 0(x1)` 紧跟 `add x7, x6, x2`（load-use 冒险，本次修好的重点）

以实测波形（`wave/tb_iverilog_prog.vcd`）为准，逐拍是：

| 拍 | IDU | EXU | M1 | M2 | M3 | `load_use_stall` | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T | `lw`(rd=6) | 空 | — | — | — | 0 | |
| T+1 | `add`(rs1=6) | `lw`(mem_ren=1) | — | — | — | **1** | `exu_load_use`：数据未就绪 |
| T+2 | `add` | `add`(被清空) | `lw` | — | — | **1** | `mem_load_use`；EXU 提前收下的这一份被 `EXU_inst_clear` 清成空操作 |
| T+3 | `add` | 空 | `add`(空操作) | `lw` | — | **1** | `pipe_load_use`（M2 对 load 仍是地址，必须继续停） |
| T+4 | `add` | 空 | — | — | `lw` | **0** | 三级条件全 0 → 放行；IDU 把 `add` **再送一次** |
| T+5 | — | `add`（前递编码 `3'b011` → `forward_val_wb` = `0x0000000C`） | `lw` | — | — | 0 | `EX_result = 0x0C + 5 = 0x11` ✓ 写回 `x7` |

关键点：**被清掉的那一份不带任何副作用**（`R_wen/mem_wen` 全 0），
所以不会重复写寄存器、也不会重复写内存（测试台有 `write-once` 专项检查）。

### 10.4 `mul` / `div`

乘法：`EXU` 一拍出结果，`mdu_busy` 全程为 0（`prog_mul` 里 `stall=0`）。
除法：`mdu_busy` 拉起 → 前端与访存流水冻结 → `mdu_done` 那一拍放行 `EX_result`。

### 10.5 分支 / 跳转 / `ecall`

- `beq`：`branch_flag=1`，EXU 把比较结果归一化到 `EX_result[0]` → `branch_taken`；
  与预测不符则 `bp_mispredict` 一次脉冲 → `dnpc` 取真实目标或 `EXU_pc+4`。
- `jal`：`jump_flag=1`，目标 = `EX_result`（`pc_d + imm`），返回地址随指令带在 `rd_value` 里。
- `ecall`：译码级识别 → `Control.system_redirect` → `dnpc=mtvec`；**它自己**继续沿流水
  走到 WB，在那里写 `mcause/mepc`（这就是 §9.2 必须把 `system_redirect` 从
  `EXU_inst_clear` 里去掉的原因）。
- 中断：`intr_pending` 拉起后，只有 `intr_safe` 成立（当前指令不是 branch/jump/fence/ecall/mret，
  且没有 load-use 暂停、MDU 不忙）才 `intr_take`，保证 `mepc` 指向真正被中断的指令。

## 12. 已知限制（本机无法完成、需要你在有工具链的机器上补）

1. **真实综合与实现**：本机没有 Vivado / yosys，给不出 LUT/FF/BRAM/DSP 实际数，
   也无法确认 BRAM 推断（`board/sync_mem.sv` 是行为模型，上板请换 `xpm_memory_*` 或 IP）。
2. **时序**：无 WNS/TNS/Fmax。建议从 **50 MHz** 起步（复位同步器与同步存储都是按这个量级写的），
   再用 `syn/timing_sweep.tcl` 逐步收紧。
3. **`cdp-tests` 47 条全指令表 difftest**：缺 verilator + make，本机跑不了。
   替代回归是 §11.1 的 103 项检查，覆盖面对比 47 条全指令表要窄（例如 CSR 全字段、
   `fence.i` 组合、各类立即数边界），**建议补跑**。
4. **板级实测**：`board/` 只做了仿真冒烟；7 段码/LED/UART 的板卡译码模块需要按你的板子补。
5. `MDU.sv`（原版单拍组合）已不在上板路径上，但仍在工程里；若你确认不再需要，可以删掉。

## 13. 一页速查：模块 → 作用

| 模块 | 一句话 | 最关键的两个接口 |
| --- | --- | --- |
| `myCPU` | 例化 + 连线 + 三路暂停合并 | `irom_*` / `perip_*` |
| `IFU` | 维护 PC，把取指可用性翻译成 `valid` | `dnpc/dnpc_flag` ↔ `inst/valid` |
| `ICache` | 同步 IROM 的请求/响应握手 + 缓存 | `cpu_addr` ↔ `mem_en/hold/fetch_align` |
| `Branch_Predictor` | gshare 方向 + BTB 目标 | `fetch_pc` ↔ `pred_taken/pred_target` |
| `IDU` | 译码：主控 + 操作数 + 系统事件 | `inst_in/pc_in` ↔ 一群 `*_next` |
| `Reg_Stack`/`RegisterFile` | 寄存器堆读口 / 32×32 寄存器堆 | WBU 写口 ↔ `rs1_value/rs2_value` |
| `CSR` | 机器模式 CSR + 中断 pending | `csr_wen/csrd/ecall/mret` ↔ `mepc/mcause/intr_pending` |
| `Control` | 重定向 / 前递 / load-use / 清空 | 各级 `rd/mem_ren/valid` ↔ `dnpc/EXU_rs1_in/EXU_inst_clear` |
| `Data_hazard` | 只产前递**编码** | `IDU_rs*` + 各级 `rd` ↔ `IDU_rs*_choice` |
| `EXU` | 运算 / 分支 / 跳转 / 预测校验 / MDU 握手 | `add1/add2/alu_opcode` ↔ `EX_result/*_next` |
| `ALU` / `add` | 组合运算器 / 加减小单元 | `d1/d2/choice` ↔ `res` |
| `MDU_pipelined` | 乘 1 拍 / 除多拍 | `start/d1/d2/op` ↔ `res/busy/done` |
| `LSU` | 三级访存流水（M3 才是 load 数据） | `Ex_result/mem_ren` ↔ `addr/rdata/forward_val_wb` |
| `DCache` | 缓存 + 同步 DRAM 握手 + MMIO 直通 | `cpu_*` ↔ `mem_*` |
| `WBU` | 四选一写回 | `*_in` ↔ `rd_value_next/R_wen_next` |
| `board/*` | 同步存储 / 复位同步 / 上板顶层 | `sys_clk/btn_rst_n` ↔ `debug_*` |
