## 1. 这次做了什么

**上板改造（P0~P4）**
- `ICache` / `DCache` 从"假设零延迟组合读"改成**同步存储握手**（请求/响应两拍、`hold` 停拍重试、未命中返回 `` `NOP ``）：
  这是上板最大的拦路虎（FPGA 的 BRAM 必然同步读）。
- `DCache` 另外：store 请求寄存成**单拍写脉冲**（一次 store 只写一次）、MMIO/uncacheable 地址**不经缓存直通**
  （否则读不到外设副作用、写不进外设）。
- `LSU`：`mem_hold` 并入 `lsu_freeze`，整条访存流水**同步冻结**（不冻全的话 hold 会自己把自己解掉）。
- `IFU`：`valid` 按**当拍取指契约**产生（原来恒为 1），PC 只在"确实交付了一条真指令"时前进，
  重定向不被存储停拍门控。
- `EXU`：接入 `experimental/MDU_pipelined.sv`（乘法 1 拍、除法多拍由 `mdu_busy` 冻结流水）。
- 新增 `board/`：`sync_mem.sv`（一拍读延迟 BRAM 模型）、`reset_sync.sv`（复位异步置位/同步释放）、
  `board_top.sv`（CPU + 两块同步存储 + 调试观测口）、`tb_board_top.sv`。
- 新增 `sim/`：自包含 iverilog 测试台 + 三个程序 + D-Cache 单元测试 + 运行脚本 + README
  （本机没有 verilator/make，跑不了原 `cdp-tests`，这是替代护栏）。

**修掉的 6 个真实 RTL 缺陷**（4 个是上板改造暴露出来的，2 个是 4 态仿真才暴露的）

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | `lw` 后紧跟的 `add` 得到 `0x1005`（地址 + 5） | EXU 级若是 load，`EX_result` 是地址；负载数据只在 LSU **第三级** `forward_val_wb` 才是数据 |
| 2 | 第一次重定向后整机死循环，`ecall` 永远到不了 WB | `bp_mispredict` 是电平信号 → 连环重定向；EXU 的 `valid` 与控制寄存器不同步，残留标志还在产生重定向 |
| 3 | `ecall` 不产生异常（`mepc/mcause` 恒 0） | `EXU_inst_clear` 含 `system_redirect`，在 ecall 被收下同一拍清掉了它的 `csr_wen` |
| 4 | `add x7,x6,x2` 算出正确 `0x11` 却写不进 x7 | EXU 的 `valid_next` 在下游未就绪那一拍被清 0，而 payload 是冻结保持 → 写回被 `R_wen & valid` 掐掉 |
| 5 | 写回永不发生（仿真里全是 `x`/`z`） | `myCPU` 里 `WBU` 的 `.stall` **悬空**（`if(!z)` 判成 x） |
| 6 | x0 初值是 `x` | `RegisterFile` 没有复位分支 |

## 2. 验证结果（可复现）

```bat
cd share\v9
sim\run_iverilog.bat                :: prog      35/35  PASS
sim\run_iverilog.bat prog_mul       :: prog_mul  34/34  PASS
sim\run_iverilog.bat prog_div       :: prog_div  34/34  PASS
```

- 三个程序 **103/103 全过**；加 `+no_wbu_force +raw_rf`（不用测试台任何兜底）**同样全过**。
- 测试台内置上板专项检查：`write-once (store not repeated)` PASS、`fetch-align (pc<->inst coherent)` PASS。
- `sim/tb_dcache_unit.sv`：miss→fill、二次命中、MMIO 不缓存、外设副作用可见 —— 全 PASS。
- `iverilog -g2012 -Wall` 整机编译：0 个隐含定义类 warning；只剩 3 条数组复位循环的保守提示与
  `timescale` 继承提示（均无害，已在 `docs/模块阅读文档.md` §5 说明）。

## 3. 本机**没能**做的（需要你在有工具链的机器上补）

1. **真实综合/实现**：本机没有 Vivado / yosys / make / verilator，所以
   LUT/FF/BRAM/DSP 实数、**WNS/TNS/Fmax**、BRAM IP 推断都没做（`board/sync_mem.sv` 是行为模型，
   上板请替换成 `xpm_memory_*` 或 IP）。
2. **原 `cdp-tests` 的 47 条全指令表 difftest**：缺 verilator + make，跑不了；
   替代回归是上面 103 项检查，覆盖面不如 47 条全指令表，**建议补跑**。
3. **板级实测**：`board/` 只做了仿真冒烟，没有比特流、没有开发板测试；
   7 段码/LED/UART 的板级译码模块需要按你的板卡引脚补。
4. `figures/` 里的三张 `v9_postboard_{prog,prog_mul,prog_div}.svg` 已用**改造后**的 VCD
   重新生成（命令见 `v9/README.md` 的「波形 / 时序图」一节）；改造前的旧图已删除。
